# Trusted schema v1 — GO-310 / GO-100-D

`baseline_v1.json` содержит только публичные SQL/metadata структуры:72 таблицы,606 столбцов,73 явных индекса,50 FK и22 триггера,217 DDL действий. Действия воспроизводятся из принятой schema-only baseline скриптом `python3 scripts/trusted-schema-policy.py`. Uploaded backup metadata/SQL сюда не попадают.

`Inspect` читает только information_schema через интерфейс с одним QueryContext. Полный контракт включает engine/collation/row format; порядок, тип, NULL/default/generated/charset/collation столбцов; primary/unique/prefix/ignored indexes; CHECK expressions; FK columns/order/rules и привязку к текущей schema (чужая reference schema отклоняется); trigger event/timing/body/SQL mode. Не сравниваются volatile AUTO_INCREMENT/cardinality/оценки строк и имя SQL definer. Для просмотра trigger body MariaDB требует TRIGGER privilege; CI использует guarded account и read-only transaction, не выдаёт дополнительные права SELECT-only пользователю.

`Preflight` не выполняет DDL и не читает бизнес-строки. Он отклоняет неизвестные/изменённые объекты и повреждённые определения существующих таблиц; отсутствующие таблицы и добавляемые объекты планирует в исходном проверенном порядке. `CheckFull` принимает только полную схему. Проверка пустоты partial schema, ownership, исполнение и повтор DDL относятся к отдельной GO-311.

Server-normalized metadata получены из guarded read-only CI job122706734570, capture commit2a014e6 (PR #70):72 tables,606 columns,269 index-column rows,117 CHECK,51 FK-column rows/50 constraints,22 triggers. `Preflight` при отсутствии verified metadata возвращает `ErrUnverified`; после встраивания требуется повторное exact full schema comparison в CI. Для FK добавлен marker CURRENT из доверенного unqualified REFERENCES; повторный SQL read сверяет его с фактической referenced schema, без привязки к имени itmap_ci. Промежуточный capture не считался приёмкой GO-310. После проверки повторные CI runs печатают только итог сверки, без повторной публикации всего metadata. Production/личные backup не используются.

Для инициализации выбрана отдельная служебная команда перед запуском HTTP: существующий сервер требует готовую baseline уже при открытии DB pool. Автоматический startup DDL и новый migration framework не добавляются. Импорт структуры в реальную базу этим PR не разрешается и агентом не выполняется.
