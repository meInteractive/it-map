# Scheduler attempts и бюджет — GO-313

`JobLease.StartAttempt` создаёт один opaque execution handle на текущую lease. ID воспроизводим из приватного случайного owner token и generation/job, выглядит как исходный UUID и не является credential. Повтор после успешного или неопределённого COMMIT возвращает `ErrAttemptReplay`, без нового handle. Схема не меняется: используются существующие scheduler_attempts, scheduler_jobs/runs и app_runtime_generation.

`Attempt.Run` выполняет ровно один явно запрошенный callback после durable reserve. SQL TX удерживает generation/run/job/attempt row locks; бюджет считается глобально по всем scheduler_attempts, включая расходы и резервы старых поколений, по исходным границам московских суток/месяца. Учитывается coalesce(cost_usd,reserved_usd). Отсутствующие лимиты равны нулю; неправильный тип/нефинитное значение не разрешают платный запрос. Free upper=0 сохраняет исходное исключение из budget ceiling.

После COMMIT выполняется повторная ownership-проверка, затем callback вне SQL TX. Его context ограничен оставшейся run/job lease и максимумом100s. Библиотека сама не вызывает сеть, не читает provider keys и не повторяет callback/SQL COMMIT. Реальный paid adapter дополнительно обязан использовать свой уже предусмотренный durable provider operation identity; здесь не активируются provider protocols или dispatcher.

Приоритет стоимости соответствует исходному schedulerBilling: конечный неотрицательный usage.cost → free=0 → исторический OpenAI token tariff только без cached input → unknown. Подтверждённая стоимость заменяет соответствующий upper reserve; credits не освобождают USD. Исторические тарифы из GO-079 — fixture compatibility, не утверждение актуальных цен и не разрешение платных вызовов.

Неопределённый ответ, SQL settlement failure, потеря владельца, expiry/restore или crash оставляют положительный reserve. Тот же handle и последующая paid attempt того же job не получают разрешения на слепой повтор до подтверждения provider ledger. Новый free шаг может завершиться, сохранив старый резерв. Это намеренное fail-closed выполнение no-blind-POST критерия GO-045/313: старый JS сохранял сумму, но сам schedulerBilling не запрещал следующий прямой вызов. Автоматического освобождения, повторного платного POST или скрытого reconciliation здесь нет; wiring подтверждения provider ledger и стадий относится к GO-046/соответствующему adapter.

`Attempt.Finish` сохраняет terminal/deferred attempt receipt и завершает/откладывает job в одной fenced TX. Любой поздний SQL fault откатывает обе записи. Известная стоимость фиксируется как cost_usd=reserved_usd, unknown остаётся NULL; recovery сохраняет деньги и исходный result_json. Публичный receipt ID не позволяет восстановить execution handle.

Source gate выполняет неизменённые JS dispatcher+schedulerBilling на38 синтетических SQLite :memory: случаях: explicit/free/token/cached/unknown precedence, budgets и old-run spend. Required disposable MariaDB сравнивает этот результат; отдельный parent проверяет два реальных соединения, limit/release, same-handle replay, generation rotation, lease deadline, late faults/joint rollback, actual COMMIT с ошибкой после успешной записи и SIGKILL между reserve и settlement. Положительные SQL-тесты разрешены только после GitHub/target/nonce guard. До успешного полного CI GO-313 открыта.
