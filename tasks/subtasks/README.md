# Малые задачи спринта 1.1

Этот каталог дробит **оставшиеся средние и низкие части спринта 1.1**, не относящиеся к парсеру и AI. Текущий главный маршрут разработки остаётся в [GO-396…407](../SPRINT-01-PARSER-APIFY.md); задачи здесь независимы от него. Не брать критические части родительских GO-задач, production, реальную БД, сетевые секреты, платные сервисы и внешние аккаунты. Календарь, экспорт и операции агентств здесь разбиты только на безопасные части с синтетическими данными; live-подключение и финальная приёмка родительских эпиков остаются отдельно.

**Как выбирать работу:** идти по таблице сверху вниз. Блоки 01–08 имеют средний приоритет, 09–10 — низкий. Внутри пачки три группы A/B/C по десять небольших пунктов. Найти **первую группу, где в строке «Отчёт» ещё стоит `PR —`**; подготовленная группа с записанным PR пропускается даже при незакрытых `[ ]`, поскольку приёмка Codex может идти позже. Доводить группу до одного небольшого PR; в рамках группы допускается отдельный PR на реально независимый дефект, но не создавать PR на каждую строку. Брать следующую группу после опубликованного PR предыдущей; если её код является зависимостью, использовать проверенную вершину предыдущей ветки. Не изменять общие реестры и файлы парсера/AI при исполнении этих задач.

**Что считать выполнением:** перед работой проверить уже существующие тесты и код, включая слитые PR #155–185; не копировать готовое покрытие. Каждая строка требует наблюдаемого поведения или конкретной проверки, а не теста, повторяющего реализацию. Исполнитель записывает в «Отчёт группы» PR, точный SHA, выполненные ID, фактически запущенные тесты, CI и ограничения. Если тест нельзя запустить, написать «не запускался». `[x]` у отдельных пунктов ставится **только после независимой проверки и приёмки Codex**; подготовленный PR сам по себе оставляет `[ ]`. Codex может проверить сразу несколько групп или пачек, после чего отмечает принятые ID и оставшиеся дефекты. Не заявлять закрытие родительского GO-ID на основании только этой пачки.

**Технические границы:** использовать существующие React/Go-компоненты и тестовую инфраструктуру; новые API, схема MariaDB, зависимости, workflow, серверная конфигурация и ключи не входят в эти малые PR. Если для сценария неизбежно нужен такой слой, подготовить воспроизводимый failing test и записать блокировку вместо подмены результата моками. Для календаря и экспорта допустимы чистые преобразования и mock-контракты, но OAuth/внешние вызовы, реальные данные и публикация остаются вне этого каталога. Для GO-032 допускается ограниченное исправление существующего CRUD/пересчёта без нового API или схемы. Код и UI менять только при подтверждённом дефекте в пределах группы. Соблюдать [AGENTS.md](../../AGENTS.md).

**Обозначения:** `M` — средний приоритет, `L` — низкий; `GO-NNN` указывает родительскую задачу. ID `S11-Bxx-yy` постоянный. В группах по умолчанию один PR на десять пунктов, всего не больше трёх PR на пачку. Ветка — `codex/GO-NNN-bxx-a` (или `b`/`c`), где GO-NNN — основной родитель группы; PR открывать к проверенной предыдущей ветке при зависимости либо к актуальной `main`. Автоматически не сливать. Для следующего исполнителя достаточно открыть этот индекс и **только файл текущей пачки**: выполненные старые файлы загружать не требуется.
