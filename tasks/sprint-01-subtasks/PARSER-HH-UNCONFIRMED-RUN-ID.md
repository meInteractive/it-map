# GO-441 / S11-DIAG-08 — оплаченная HH-операция без подтверждённого Run ID

**Основание:** по коду фаза `reconcile` считала запись `apify_runs` готовой для GET только по факту её наличия. Между тем `Service.reconcile` требует непустого `run_id` и возвращает `ErrUncertain` в случае неопределённого исхода. Повторный платный POST не должен происходить ни при каких обстоятельствах без подтверждённой безопасной цепочки.

**Область:** чтение `run_id` из существующего `apify_runs` в `readClaimView`; фаза `launch` и `reconcile` обе отвергают известную оплаченную операцию без Run ID. Для прочих операций поведение не изменяется. Добавить `unconfirmedRunId` (подмножество `pendingBreakdown.other`) и `oldestUnconfirmedAt` в GET-only HH-диагностику и whitelist копирования JSON, не экспортировать ledger или идентификаторы.

**Тесты:** синтетический случай `starting/uncertain` без Run ID отвергается обеими фазами, сохранённый Run ID разрешает GET, но запрещает второй POST. Числовая разбивка остаётся взаимоисключающей, orphan/blocked/cooldown работают по-прежнему. JS JSON test сверяет whitelist, `null` для старого backend, отсутствие private поля. Обязателен весь repo CI на точном SHA PR и публикация только через ручное слияние.

**Границы:** никаких изменений схемы/данных production, новых API, worker timing, Actor POST, budget или ручного исправления очереди. Не интерпретировать потенциальную кодовую проблему как доказанный диагноз конкретного провайдерского запуска.

**Отчёт:** PR —; SHA —; CI —; эксплуатационная сверка — не проводилась.
