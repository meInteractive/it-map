**Дополнение 20.11.2026 — PR #513 (B05/A: безопасный повтор + UI-права), к проверке Codex.** В `VacancyEditor` после PUT с неопределённым результатом следующий save **не отправляет второй PUT до прямого `GET /api/vacancies/{id}` без кэша и сверки исходной `revision`**. Если revision изменилась (включая случай COMMIT с потерянным ответом), показывается конфликт, старый черновик сохраняется, повторная запись блокируется. После настоящего `409/428` прямой повтор также блокируется до повторного открытия редактора. Добавлены два browser-сценария для B05-08 (ответ `503` без применения и ответ `503` после COMMIT) и один UI-сценарий B05-10 (обычный пользователь читает список/карточку, но не видит создание/редактирование); каждый выполняется в desktop/mobile. **B05-10 — UI часть добавлена; серверные отрицательные права уже покрываются отдельными SQL/HTTP-тестами**: `TestMariaDBVacancyEditHTTPDisposable` проверяет `demo PUT → 403`, `TestMariaDBVacancyCreateHTTPDisposable` проверяет `demo POST → 403`; оба target явно перечислены в `.github/workflows/mariadb-staging-ci.yml`. Приёмка всей связки UI→Go/MariaDB и Codex-review ещё не завершена. **B05-09 не начинали**: текущий `VacancyEditor` получает фиксированного владельца из карточки компании и не имеет UI выбора нового владельца. В Go `internal/vacancies/update.go` смена `company_name` при PUT поддержана и переносит привязанные отклики/задачи, поэтому перед открытием такого действия в UI нужно отдельно проверить бизнес-правила, валидацию owner и совместимость связанных данных. Исторический статус предыдущих 01–07 не меняется, все чекбоксы `[ ]`.
