**Цель:** до любых реальных `cancel/retry` показать безопасные числовые агрегаты о наличии сохранённых Run ID, Dataset ID и Metadata, а также совпадении ключа текущей страницы с `apify_runs` и наличии провайдерского Run ID. Эти числа **не гарантируют** отсутствие оплаченных предыдущих страниц, не доказывают отсутствие потерянного POST и не являются разрешением на повтор. Ни один отдельный показатель не является обещанием безопасного восстановления.

**Границы:** использовать существующий транзакционный GET `ReadHHScanSchedule`, в памяти дополнять read-only proof с сохранённых cursors и уже считанного `apify_runs`, без новых провайдерских запросов, записи БД, API endpoint, SQL-миграции или изменения scheduler, claim и бюджета. Go/JS синтетические тесты, playbook, handoff.

**Приёмка:** Go-тесты сохранённых полей и пересечения ledger текущей страницы, JS тесты секретов и `null` для старого backend, три обязательных CI на head SHA, ручной merge. Потом свежий обезличенный снимок, оценка read-only preflight и только отдельно согласованные действия с production.
