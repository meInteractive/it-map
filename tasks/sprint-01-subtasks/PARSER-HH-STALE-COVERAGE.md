# GO-440 / S11-DIAG-07 — разбивка HH без подтверждённого полного успеха

**Основание:** анализ `parser_hh_schedule` от 10.11.2026. Данные обезличены: при 30 включённых HH-источниках 25 подтвердили успешный полный обход за последние 48 часов, трое имели локальные задания, однако ни у одного свободного источника срок проверки не наступил. Старейшее задание создано 04.11.2026. Эти показатели не объясняют сами по себе конкретную причину задержки.

**Подтверждённое поведение:** при `partial` полный успех не фиксируется, но срок обновляется; очередное платное сканирование не должно автоматически дублировать старый Actor. Нельзя восстанавливать неподтверждённый курсор без безопасной идентификации и доказательств.

**В этой порции:** расширить существующий read-only HH GET и JSON whitelist числовыми категориями источников без полного успешного обхода за 48 часов (ожидают срока / имеют HH-задание / срок наступил) с отдельным числом partial среди ожидающих. Разделить `unverifiedCursor` на происхождение/версию и отсутствие подтверждённого ключа операции; показать возрастные метки по категориям без IDs. Прежние имена и значения сохранить.

**Тесты:** чистые Go unit-тесты границ 48 часов и взаимоисключающих категорий, сохранение прежних API-контрактов; синтетические UI/JSON тесты с несогласованным ответом, старым сервером и приватным payload; `node scripts/check-api-coverage.mjs`, TypeScript, формат, сборка, штатный Go/CI и изолированная MariaDB. Производственная приёмка — только после отдельного разрешения.

**Не делать:** DDL, боевые UPDATE/INSERT, платные вызовы, ручной POST Actor, изменение кулдауна, бюджета, таймера, генерации очереди или API авторизации. Результат объясняет состояние, не снимает ограничения безопасности.
