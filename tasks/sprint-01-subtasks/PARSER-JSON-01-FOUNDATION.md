# S11-DIAG-01 — единый безопасный экспорт JSON из разделов парсера

**Статус:** [ ] Разработка ведётся в [PR #259](https://github.com/meInteractive/it-map/pull/259). Основа написана; проверка CI и последующая приёмка не завершены. Кнопки на реальных страницах ещё не подключены. **Приоритет:** высокий в диагностических улучшениях, без обгона обязательных GO-107 → GO-108. **Формат:** одна небольшая реализация в чате/отдельный PR, без Codex Cloud. **Эпик:** диагностика спринта 1.1; интеграция с GO-107 и GO-108. Не запускать платных провайдеров.

## Цель

Повторно используемый компонент кнопки **«Копировать JSON»** во всех диагностических блоках. Значения берутся из уже полученной в авторизованном приложении информации и, только если необходимо, из нового read-only серверного агрегата. Нельзя просто копировать произвольный API response: в исходных `result_json`, payload, ошибках и настройках могут быть секреты/персональные данные.

## Требования

- [ ] **S11-DIAG-01-01.** Проверить существующий код `frontend/features/settings/{Scheduler,ParserIssues,ParserFunnel,Apify,Firecrawl}.tsx`, `frontend/api/client.ts`; существующие права backend и формат данных. Составить белый список полей для каждой секции до реализации.
- [ ] **S11-DIAG-01-02.** Создать переиспользуемый `CopyDebugJSON` (название условное) с компактным расположением около заголовка блока, `type="button"`, клавиатурным управлением, screen-reader status и корректной обработкой `navigator.clipboard.writeText` ошибок. Никаких ложных сообщений «скопировано».
- [ ] **S11-DIAG-01-03.** Единый **versioned** envelope `schemaVersion: 1`, `section`, `capturedAt` ISO UTC, `timezone: "Europe/Moscow"`, `appVersion`/SHA при достоверном наличии, `filters`, `summary`, `recentItems` и `dataAsOf` для кэшированных снимков. Не выдумывать commit/SHA/момент измерения.
- [ ] **S11-DIAG-01-04.** Длинные списки ограничить **последними 10 элементами по времени события**, с tie-break по ID. Передавать `total`, `returned`, `limit: 10`, `truncated`, исходный фильтр и правила сортировки. **Не ограничиваться текущей страницей** очереди или произвольными первыми десятью. Для 30-дневных графиков сохранить **все 30 агрегированных дней**, поскольку это не события.
- [ ] **S11-DIAG-01-05.** Состояние недоступности отражать `available: false`, машинным `errorCode`, временем последнего успешного чтения (если известно), без замены отсутствующих метрик на `0`. `null` для неизвестной суммы/времени; ноль только для доказанного нулевого значения. Не путать `pending`, `deferred` и `failed`.
- [ ] **S11-DIAG-01-06.** В экспорт включать **только администраторские диагностические поля**, с явным allowlist. Запрещено: provider keys/токены, cookies, session IDs, auth headers, секреты, резюме, промпты, текст ответа модели, полный текст вакансии, произвольные source URL с query/token, сырые `payload`/`result_json`, `last_error`/`message` без очистки и полные провайдерские HTTP-ответы.
- [ ] **S11-DIAG-01-07.** Не расширять права через API: при необходимости нового endpoint — проверка сессии и роли администратора на Go, bounded timeout, параметризованный SQL, ограничение выборки, отсутствие side effects/DDL; не делегировать фильтрацию секретов только React. При запросе после logout нельзя копировать старый кэш другого пользователя.
- [ ] **S11-DIAG-01-08.** Детерминированный JSON с едиными типами времени (ISO UTC, при необходимости исходный epoch миллисекунды отдельно с явной единицей), бюджетов (USD отдельно от кредитов), стабильной схемой и ожидаемой обратной совместимостью. Форматирование `JSON.stringify(data, null, 2)`; ограничить общий объём (например, 200 KiB), обрезая только списки с явным `truncated` — не обрезать JSON-строку посередине.
- [ ] **S11-DIAG-01-09.** Проверить, что копирование **не запускает** Apify, Firecrawl, OpenAI, OpenRouter/JEV, синхронизацию баланса, диагностические POST, перерасчёт со скрытой записью, retry или изменение статуса заданий. Не менять действующие бюджеты/таймеры. Нужная для JSON дополнительная информация должна иметь безопасный отдельный GET.
- [ ] **S11-DIAG-01-10.** Unit-тесты формы/serializer на синтетических данных (включая секреты в полях, >10 элементов, одинаковый timestamp, пустые списки, ошибку Clipboard API, `null`), browser desktop/mobile и admin/non-admin, `npm run build:web` и обязательный CI на точном SHA. Существующий `public`-repo check обязателен.

## API / форма

```json
{
  "schemaVersion": 1,
  "section": "scheduler_queue",
  "capturedAt": "2026-11-07T12:00:00.000Z",
  "timezone": "Europe/Moscow",
  "filters": { "status": "pending", "type": "scan_source" },
  "summary": { "total": 0 },
  "recentItems": {
    "total": 0, "returned": 0, "limit": 10,
    "truncated": false, "items": []
  }
}
```

Пример исключительно синтетический. `section` определяет контракт конкретной кнопки; общая диагностика добавляется позже в S11-DIAG-05.

## Границы и зависимости

- GO-107 и GO-108 **сейчас важнее**. Общий компонент полезно сделать до первых UI-кнопок, но его нельзя использовать как причину откладывать исправление отсутствующих Go endpoints.
- В каждом последующем пункте сначала использовать `CopyDebugJSON`; не дублировать реализацию clipboard и проверку безопасности.
- Кодовый PR не сливать автоматически. **Отчёт:** PR [#259](https://github.com/meInteractive/it-map/pull/259); рабочая ветка `codex/S11-DIAG-01-safe-json-copy-foundation`. Ключевые файлы: `shared/debug-json.mjs`, `shared/debug-json.d.mts`, `frontend/features/settings/CopyDebugJSON.tsx`, `scripts/test-debug-json*.mjs`; обязательный запуск тестов добавлен в web CI. **Точный HEAD SHA и окончательный результат CI смотреть в GitHub на момент проверки**, не переносить статус прежнего коммита. Реализован только общий компонент/формат (no API/SQL/provider changes); в GO-107/108 и S11-DIAG-02…05 ещё потребуется интеграция с фактическими безопасными DTO, проверкой admin/session и desktop/mobile browser. Чекбоксы остаются открытыми до приёмки.
