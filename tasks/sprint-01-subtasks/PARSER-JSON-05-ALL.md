# S11-DIAG-05 — «Копировать всю диагностику» и сквозная приёмка

**Статус:** [ ] Запланировано, после S11-DIAG-01…04, GO-107/108. **Приоритет:** средний. Один отдельный PR; не собирать полный raw дамп ни с сервера, ни из браузера.

## Назначение

Одна кнопка **«Копировать всю диагностику»** на вкладке «Обзор». После нажатия пользователь может вставить в ChatGPT **один безопасный JSON**, включающий основные данные, все доступные агрегаты и последние 10 записей каждого длинного списка. Это **планируемая функция**, а не существующая возможность.

## Содержание

- [ ] **S11-DIAG-05-01.** Общий envelope `schemaVersion/capturedAt/timezone/appVersion`, `sections` и отметки полноты каждого раздела. Использовать сериализаторы S11-DIAG-01…04, не формировать новую схему параллельно.
- [ ] **S11-DIAG-05-02.** `schedulerOverview`, `queue` (последние 10 **под выбранными фильтрами**, с указанием этих фильтров), `runs` (10), `attempts` (10), `aiSpending`, `apify`, `firecrawl`, `issues`, `funnel`. Не создавать новые HTTP-вызовы к внешним поставщикам; запрашивать только safe read endpoints.
- [ ] **S11-DIAG-05-03.** При недоступности GO-107/108/Firecrawl переносить только `available:false` и `errorCode`, не блокировать копирование остальных секций и не подменять отсутствие данных нулями.
- [ ] **S11-DIAG-05-04.** Указать `capturedAt`, а для каждой секции отдельно `dataAsOf` и признак устаревших данных. Не смешивать показания разных источников без пояснения различий периода, поколения, единицы измерения.
- [ ] **S11-DIAG-05-05.** Размер JSON ограничить прогнозируемо (начально целевой предел 200 KiB), сохраняя валидность `JSON.parse`, все 30 дневных агрегатов и обязательную метаинформацию; при превышении уменьшать optional event lists с точным `truncated=true`, но не терять причины проблем. Программный reset-флаг для тестов.
- [ ] **S11-DIAG-05-06.** Реализовать безопасную копию для чата по умолчанию; **не** добавлять вторую кнопку «сырой JSON» в обход маскирования. Администраторский доступ, общий allowlist, запрет кодирования PII/ключей (включая поля `message`, `payload`, `result_json`) и отсутствие повторного показа чужой сессии.
- [ ] **S11-DIAG-05-07.** Добавить статическое пояснение UI: «Скопированный JSON содержит техническую диагностику; перед отправкой третьим лицам проверьте содержимое». Указание не заменяет обязательное автоматическое удаление секретов.
- [ ] **S11-DIAG-05-08.** Контрактные тесты на каждый section: отключённый парсер, ошибки API, пустые списки, 150+ записей в очереди, 30-дневные агрегаты, три разных времени обновления, unknown costs, partial timeout, испорченный error message с секретом, logout между началом и копированием.
- [ ] **S11-DIAG-05-09.** Проверить desktop/mobile и clipboard permissions/отказ, без запуска платных Actor или LLM. `npm run build:web`, relevant Go/SQL tests и GitHub CI на точном SHA.
- [ ] **S11-DIAG-05-10.** Обновить [инструкцию диагностики](../../docs/dev/PARSER_DIAGNOSTICS_PLAYBOOK.md): добавить раздел «Реализовано» только после слияния и сквозной проверки; до этого держать пометку **«Планируется»**.

**Граница:** этот экспорт — наблюдаемость, **не** самостоятельный монитoринг, сбор персональных данных, live-трассировка HTTP, изменение лимитов или управление парсером. Источником истины остаются provider ledger и MariaDB.
