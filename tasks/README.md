**Идентификаторы:** `GO-NNN` постоянные, никогда не переиспользуются; GO-001…GO-028 соответствуют исходным `1.1.01…1.1.28`. Поздние GO-101+ и GO-301+ уже выделены и в текущем спринте; новые ID проверять по всем `tasks/SPRINT-*.md`, сохранять связь с исходной задачей и объяснять зависимость.

**Статусы:** `[x]` только при завершённых критериях и проверенном результате; `[ ]` означает не принято целиком. Наличие Go-кода, успешного `go test` или упоминания в старом отчёте не закрывает задачу, если она требует staging, реальной MariaDB или end-to-end теста. Коммиты в незакрытой задаче отражают подтверждённый **частичный** код. Если тест не выполнялся, прямо писать «не запускался». GitHub PR и ручную приёмку фиксировать в самой задаче, не удалять историю.

**Цикл Codex (уточнён пользователем 25.10.2026):** выбрать следующую доступную GO-NNN из утверждённого плана → прочитать исходники и проверить зависимости → отдельная ветка от вершины предыдущей проверенной ветки → реализация → тесты/сборка/статический анализ → отдельный коммит → stacked PR в предыдущую ветку → обновить статус/результаты/блокировки → сразу продолжить следующую независимую задачу без ожидания merge или промежуточной приёмки. Первый PR стека направляется в main. Родительский PR указывается в описании дочернего; изменения просматриваются последовательно снизу вверх. Не выполнять автоматический merge, удаление действующего кода или изменения продуктивной инфраструктуры.

При небезопасном исправлении или архитектурном решении блокировать эту задачу и зависимые от неё, продолжать независимые разрешённые части. Внешний staging и согласованный снимок не подменять синтетической CI-базой. Недоступность GitHub API/прокси не мешает локальным коммитам и отчёту; PR считается созданным только после подтверждения API. Новые PR и комментарии оформлять по-русски. Контрольные точки стека: [STACK.md](STACK.md).
