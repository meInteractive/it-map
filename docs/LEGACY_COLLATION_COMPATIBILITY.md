# GO-100-C-P: решение о Unicode-порядке старого каталога

Только sprint1.1, backup v14–15. Runtime Go пока принимает v16–39; предложенный comparator не подключён. Entity fields приняты отдельно в #60. Этот документ фиксирует конкретное отличие, требующее решения до завершения legacy plan.

## Наблюдение

Node24.19 / ICU78.3 / CLDR48 / Unicode17 не всегда считает равными канонически эквивалентные последовательности при `localeCompare(other, "ru")`. Это воспроизводится на Cyrillic И/и, двух новых комбинируемых знаках Nag Mundari и следующем диакритическом знаке. `.normalize("NFD")` подтверждает эквивалентность строк, но исходное сравнение возвращает 1.

Пример (показаны escape-последовательности, чтобы не зависеть от шрифта):

| Левая строка | Правая строка | Node `localeCompare` | Предложенный Go comparator |
| --- | --- | --- | --- |
| `\u0438\u{1E4EC}\u0308` | `\u0438\u0308\u{1E4EC}` | 1 | 0 |
| `\u0438\u{1E4ED}\u0308` | `\u04E5\u{1E4ED}` | 1 | 0 |
| `\u0418\u{1E4EC}\u0308` | `\u04E4\u{1E4EC}` | 1 | 0 |

## Подготовленный вариант

Прототип Go использует веса из того же ICU, полный Unicode17 NFD/CCC, русскую перестановку кириллицы, составные последовательности, уровни primary/secondary/tertiary и сохранение lone UTF16. Веса получены build-time из публичных Unicode/ICU-данных; ни Node, ни CGO не требуются при работе приложения. ASCII/byte sort и устаревший x/text collator не подставляются вместо исходных правил.

Получены 1 114 112 code point mappings и 1153 исходные составные последовательности. Стандартные пары, кириллица/латиница/emoji/lone UTF16 и 60 000 случайных сравнений совпали с источником. В расширенном корпусе из418748 пар (все составные последовательности с perturbations, CCC/normalization/case/random) — 8 расхождений указанной семьи. Это число относится к корпусу, а не обещание, что существует только восемь возможных строк с отличием.

Отдельная служебная последовательность ICU FDD1+AC00 сохранена по исходной таблице: полная NFD без учёта этой особенности тоже меняла бы порядок. Результат не считается принятым source-parity по одному совпадению большинства пар.

## Решение, которое нужно согласовать

Предлагается допустить канонический Unicode-порядок для названий с неканоническим порядком комбинируемых знаков при одинаковом рейтинге компаний. В приведённых случаях сравнение будет 0, поэтому сохранится исходный порядок элементов файла. Это может изменить только порядок/rank равных по баллу компаний.

Текст названий, идентификаторы, поля каталога, связи, число компаний и агентств не меняются; нормализованные строки для сортировки не записываются вместо названий. Дедупликации по нормализованному имени нет. Агентства сохраняют исходный порядок. Signed v16–39 не проходят новую нормализацию каталога и этим решением не затрагиваются.

Альтернатива — точный перенос поведения Node, включая эти случаи: продолжить перенос FCD iterator/lookahead/rollback ICU вместо канонической подготовки ключей. Это требует дальнейшей реализации и differential proof; приближённая замена не включается автоматически.

[AGENTS.md](../AGENTS.md) требует: «Любое несовместимое изменение требует согласования и обновления фронтенда/документации». Поэтому до ответа C-P не закрывается, C-S/D не включаются. Независимые критические задачи можно продолжать.

## Воспроизводимость исследования

В текущей рабочей среде исходники прототипа и oracle находятся в `/workspace/work/icu-collation/`: `generate.cc`, `compress.mjs`, `main.go`, `stress.mjs`. Они работают только с публичными Unicode-данными и synthetic strings; реальные backup/DB/keys не использовались. Производственных изменений или приёмки comparator в этом PR нет. Перед включением выбранного варианта генератор, данные, лицензия и required tests должны стать рецензируемой частью реализации.

Минимальный воспроизводитель исходного поведения (Node24):

```bash
node --input-type=module <<'JS'
const a='\u0438\u{1E4EC}\u0308';
const b='\u0438\u0308\u{1E4EC}';
console.log(a.normalize('NFD')===b.normalize('NFD')); // true
console.log(a.localeCompare(b,'ru'));               // 1 на исследованном Node/ICU
JS
```
