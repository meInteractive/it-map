# GO-336: порядок назначенных ролей вакансии

Критическая часть GO-011: исходный `attachVacancyRoles` из `server/repositories/vacancy-roles.js` сначала читает назначения в порядке `vacancy_id,role_id`, затем стабильно сортирует роли по `path.localeCompare(..., 'ru')` и собирает `role` через запятую. Go использовал побайтовое сравнение Path в списке, карточке и списке компании. Оно меняет порядок русских/латинских букв, регистр, знаки, Unicode и иерархические пути.

`roles.OrderAssigned` использует принятые канонические ключи русского порядка ADR-023, вычисляет их один раз на роль и возвращает собственный срез. Равные пути сохраняют входной SQL-порядок; имена, ID, пути и метаданные не переписываются. Все три чтения используют эту функцию. Схема, запросы отбора назначений, API и права не меняются.

Проверка `scripts/check-assigned-role-order.mjs` вызывает неизменённый `attachVacancyRoles` на настоящей SQLite в памяти с явным каталогом. 167 кадров: смешанный алфавит/регистр/диакритика/emoji, иерархии, канонически равные пути, неизвестные ID, fallback без назначения и детерминированные перемешанные наборы. Перед исправлением meaningful regression падает на порядке/названиях; после — exact DTO совпадение и отсутствие мутации входных назначений. Политика канонической Unicode-эквивалентности уже принята ADR-023; новых исключений не вводится.

Native `TestMariaDBAssignedRoleOrderDisposable` использует только guarded disposable GitHub CI на10.11. Синтетические роли/вакансии создаются разрешённым writer, все три чтения выполняются через проверенный SELECT-only account. Исходная SQLite задаёт ожидаемые полные roles и role;9 required случаев (list/detail/company × Eugene/Nastya/Demo) проверяют данные, user favorite/hidden isolation и неизменность всех72 таблиц. Контур не допускает skips. Локальный compile/skip не считается SQL-приёмкой.

На этапе реализации source167 прошёл; положительный native CI ещё ожидается. Полная GO-011 остаётся открыта: весь source SQL/API parity списка/источников/периодов, инициализация исходных данных и внешний снимок здесь не принимаются. Сервер Hetzner, реальные БД/данные/провайдеры и deploy не затрагиваются.
