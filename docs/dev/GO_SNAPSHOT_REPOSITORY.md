# GO-363: чтение полного текста из MariaDB

`ReadRawSnapshot` в транзакции вызывающей стадии читает последнюю запись указанной вакансии и её URL. Проверяются status=valid, полный Markdown или упорядоченные части, сохранённый SHA-256 и содержательное тело для rabota.ru. Старая валидная запись не подменяет новую невалидную. При двух последних снимках с одинаковым временем возвращается отдельная ошибка: исходный SQLite использует rowid для разрыва равенства, а целевая схема не хранит этот порядок и безопасно угадать его нельзя.

Владелец, scope и актуальный URL проверяет вызывающая стадия в той же owned транзакции. Функция не вызывает провайдеры, не меняет строки и не запускает очередь. Изолированный required MariaDB gate сравнивает семь actual `currentRawSnapshot`/`snapshotMarkdown` сценариев с неизменённой JavaScript-реализацией; дополнительно проверяет несовпадение хеша, отсутствующую часть и неоднозначную последнюю запись. Локальный skipped SQL test не является SQL-приёмкой.

Далее GO-364 должен связать этот слой с prompt/model settings, cache, detail/LLM leases и атомарной записью результата через существующий AIStageExecutor. Только после этого можно утверждать, что стадия extraction подключена; полный parser требует также оставшихся стадий и handoff.
