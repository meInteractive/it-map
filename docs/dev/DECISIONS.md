# Журнал архитектурных решений it-map

Решения сохраняют договорённости, но **не** дают разрешения на изменение данных/production. «Принято» = концептуально утверждено, не обязательно реализовано; «предложено» = требуется согласование. «Реализовано и проверено» фиксирует технический выбор в рамках ранее принятых ADR и результат проверок; этот статус не означает отдельного пользовательского согласования новой архитектуры. Дата указана только если известна из истории проекта.

Здесь фиксируются долгосрочные решения, их мотивация и ограничения. Приоритеты и очередь находятся в [PLANS.md](../../PLANS.md), состояние веток/PR и CI — в [tasks/STACK.md](../../tasks/STACK.md), критерии задач — в [tasks/SPRINT-01.md](../../tasks/SPRINT-01.md).
