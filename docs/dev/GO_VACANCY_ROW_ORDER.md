# GO-338: порядок строк списка вакансий

Исходный `readVacancyProjectionRows` выполняет `ORDER BY company_name COLLATE NOCASE ASC, published_at IS NULL ASC, published_at DESC, id DESC`. MariaDB-схема хранит имена в `utf8mb4_nopad_bin`; прежний Go ORDER BY давал другой порядок, например Beta/Zulu/alpha вместо alpha/Beta/Zulu. Исходные имена не должны меняться ради сортировки.

`orderedVacancyRows` получает сырые SQL-строки из того же readonly RR-снимка, вычисляет один ключ компании на строку и сортирует собственный набор до DTO-проекции. SQLite NOCASE переводит только ASCII A–Z, сохраняет остальные UTF8-байты и останавливает сравнение на NUL; при равных префиксах сравнивает полную длину строк в байтах. Затем сохраняется различие SQL NULL и пустой даты, бинарный убывающий порядок полного текста даты и убывающий ID. Только после сортировки существующая project() превращает пустую дату/SQL NULL в JSON null; period filter остаётся прежним GO-318. Unicode lower и русская коллация ролей здесь не используются: это другой исходный контракт.

Неверный SQL ORDER BY убран, запрос по-прежнему читает весь согласованный набор без LIMIT; выбор строк, latest application/user state, имена, даты, схема и API не меняются. Нет GET bootstrap, provider execution и записей в БД.
