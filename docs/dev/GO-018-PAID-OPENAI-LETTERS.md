# GO-018 — явная платная генерация сопроводительного письма через OpenAI

**Область:** нативный Go API + React. Изменение только в ветке/PR, **не** разрешение на production deploy, restart, миграции, реальные платные запросы или работу с ключами.

## Причина отказа

Нативная `coverletters.Service.Generate` отвергала любой `provider=openai` с `ErrPaidBilling`. При этом уже существуют настройки и шифрованный ключ OpenAI, клиент Responses API, выбор модели и долговечная lease на пользователя/вакансию. Отсутствовал учёт ручных платных операций. Старый бесплатный путь OpenRouter (`max_price=0`) сохраняется.

## Поведение

- В карточке вакансии письмо создаётся **только по нажатию «Создать»**, даже когда пустое. Прежде пустая карточка могла запускать генерацию при открытии; для платного провайдера это недопустимый неявный расход.
- При `provider=openai` модель не заменяется бесплатной. Реальный OpenAI POST выполняется только через `paidBilling.Run`, после валидации снимка и записи evidence на текущей MariaDB.
- Без DDL используется существующая `openrouter_ai_logs` с `task=openai_cover_letter`. Ключ: SHA-256 от generation, пользователя и полной хешированной версии входа; в записи **нет** резюме, вакансии, промта, ответа или API-ключа.
- Запись `paid_unknown:<fingerprint>` фиксируется **перед** внешним POST в транзакции. Admission сериализуется под `app_runtime_generation FOR UPDATE` и действующей `cover_letter_generation_leases FOR UPDATE`; в этой же транзакции проверяются текущий Hash входа и прежние операции. SQL-lock снимается до сети. Неоднозначный COMMIT, отмена после записи, обрыв ответа, ошибка provider и повторный запуск оставляют evidence и запрещают повтор **с тем же входом**.
- Полученный HTTP-ответ переводит запись в `paid_response:<fingerprint>` с `success=1`. Это подтверждает ответ, **не** денежное списание, успешный разбор, сохранение письма или нулевую стоимость. Ошибка/отмена оставляет `paid_unknown`. Никаких компенсационных платных повторов.
- Если после получения ответа `Save` не удался или вход изменился, свидетельство платного обращения остаётся. Повтор с тем же снимком запрещён до ручной сверки. Новый явно изменённый вход — другая операция; это не reconciliation старой.
- Свежий `ErrPaidUncertain` отображается как 409 с безопасным сообщением; `ErrPaidBilling` остаётся 503 для ошибочной конфигурации.

## Ограничения и операторская приёмка

1. Текущая таблица `openrouter_ai_logs` **не является финансовым ledger**: в ней нет `cost_usd`, идентификатора OpenAI Response, itemized usage или доказательства settlement. Затраты неизвестны до отдельной сверки с провайдером; `success=1` не означает `cost=0`. Никакого автоматического размораживания, очистки или `retry`.
2. Fingerprint защищает от точного повтора; он **не** обеспечивает межкандидатную дедупликацию семантически одинаковых вводов и не заменяет GO-431 / Issue #489, относящийся к worker. Изменение промта, модели, резюме или revision создаёт новый вход и требует осознанного повторного нажатия.
3. Приложение не имеет отдельного лимита расходов для ручных писем. До production включения OpenAI владелец должен ограничить бюджет в проекте OpenAI, проверить текущие тарифы и подтвердить возможные расходы. Это не заменяет независимый ledger.
4. В CI нет реальных ключей и оплачиваемых POST. Проверяются синтетические success, lost ACK, запрет повторного POST, замена входа, сохранение старого unknown, отмена и отсутствие автогенерации. Требуются `PASS` `TestMariaDBCoverLetterGenerationDisposable` и `TestMariaDBCoverLetterPaidAdmissionDisposable` на **последнем** SHA PR; `SKIP` не принимается.
5. Перед эксплуатационной приёмкой отдельно проверить установленный SHA API, вход администратора, выбранную реальную модель и ключ OpenAI (без вывода его в чат/лог), явное нажатие «Создать», понятную ошибку 409 и provider billing. **Не выполнять реальный оплачиваемый тест без явного разрешения владельца.**
6. Дальнейший этап при необходимости: специализированная таблица immutable paid-operation admission с provider request/response id, настраиваемыми лимитами и reconciliation; миграция/rollout только через отдельное согласование и Codex.

Этот PR не изменяет парсер, worker, systemd, секреты, бюджет, существующие записи или production БД.
