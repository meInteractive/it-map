# GO-001: исторический эталон и проверка истории

25.10.2026 создана [ветка gpt-site](https://github.com/meInteractive/it-map/tree/gpt-site) ровно на `f51aacb37a03a0cef6bffcc2c590aafd803a8c3f`. Это очищенный Sites v316 snapshot, уже достижимый из ранее опубликованного main; новые приватные данные или объекты из внешнего архива не добавлялись. Новый указатель не удаляет и не переписывает main/master/feature-ветки. Исторический коммит не содержит GitHub workflow; deployment не запускался.

`git ls-remote origin refs/heads/gpt-site` подтвердил SHA. `git fsck --full --strict` успешен. Перед публикацией ref после fetch всех доступных heads проверены 119 commits / 836 уникальных blobs. Эти числа — конкретная контрольная точка до добавления данного gate, не постоянный лимит истории. Исходный src/data.json содержит 3 синтетические компании согласно boundary-документу. Приватная история/84 D1 миграции/реальные данные сознательно не входят в этот snapshot и не восстанавливаются этим действием. Исходный документ [MIGRATION_PUBLIC_REPOSITORY.md](MIGRATION_PUBLIC_REPOSITORY.md) сохранён как исторический.

## Воспроизводимые проверки

```bash
git fetch origin 'refs/heads/*:refs/remotes/origin/*'
git fsck --full --strict
python3 scripts/test_git_history.py
python3 scripts/check-git-history.py
python3 scripts/check-public-repo.py
```

History gate:

- отказывает на shallow/unreadable/unborn репозитории;
- проверяет все достижимые refs: уникальные Git blobs (включая binary) и имена файлов в каждом историческом дереве;
- использует те же известные token formats, что worktree gate; правила вынесены в общий модуль без изменения значений;
- обнаруживает файл с token или архивный/приватный путь, даже если тот удалён следующим коммитом;
- не выводит значения, содержимое blobs или имена файлов: finding содержит только object SHA и имя правила;
- не пишет в Git, не делает reset/cleanup/push и сам не обращается к сети.

Source CI получает полный checkout (`fetch-depth: 0`), запускает 6 synthetic regression tests и сканер до Go/web jobs. Тесты создают только одноразовые локальные Git repos с вымышленными значениями; synthetic token собирается во время выполнения и не коммитится в it-map. Проверяются clean repo, удалённый token без вывода значения, удалённый archive, binary token, допустимый .env.example/запрещённый .ENV, отказ на shallow clone. Python unit-тесты действительно исполняются отдельной командой, не нулевым discover.

## Границы результата

Это автоматический gate известных форматов и путей, не гарантия отсутствия любых PII, произвольного пароля, лицензированного набора или неизвестной приватной истории. Полный внешний аудит и ручная приёмка источника GO-001 остаются отдельным критерием. Не ослаблять gate при finding: сначала исследовать объект приватно, не копировать найденное значение в чат/PR/CI log. Не переписывать опубликованную историю автоматически. Реальные дампы, Sites/D1, продуктивная инфраструктура и merge этой порцией не затрагиваются.
