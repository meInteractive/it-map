# GO-431: безопасная диагностика `invalid_output` при извлечении вакансии

Вход: `extract_vacancy` → `AIStageExecutor` →
`ExtractionStageStore.SaveFailure` → `vacancy_extractions`.
Это документ о **категориях**, а не о реальных ошибках конкретного провайдера.

## Что доступно

Для `invalid_output` в `vacancy_extractions.diagnostics` (при
подтверждённой фиксации failure) может появиться необязательное поле
`outputIssue` из фиксированного закрытого набора:

| Значение | Что подтверждается |
|---|---|
| `json_invalid` | Локальный валидатор отклонил синтаксис JSON или несколько JSON-значений |
| `schema_shape` | Локальный валидатор обнаружил неправильный набор полей / структуру |
| `field_invalid` | Значение одного из полей **публичной серверной схемы** не проходит проверку |
| `content_insufficient` | Недостаточная длина обязательного содержательного текста |
| `salary_bounds` | Нижняя граница зарплаты превышает верхнюю |
| `salary_unverified` | Сумма зарплаты не найдена в исходном тексте |
| `publication_date` | Формат или значение даты не соответствует YYYY-MM-DD |
| `provider_response` | Адаптер получил неполный/некорректный ответ, отказ или пустой контент; **точная причина неизвестна** |

`descriptionIssue` по-прежнему независимо уточняет локальную проверку
`description_md`: `wrong_type`, `empty`, `null_byte`, `too_long`.

Поле `outputIssue` может **отсутствовать**: неизвестный текст ошибки, код
другого типа/статуса, ошибка сети/отмена, либо завершение до записи
`SaveFailure`. Отсутствие не доказывает исправность модели. Нельзя
восстанавливать `outputIssue` по случайному тексту в exception.

## Денежные и эксплуатационные ограничения

- Категории формируются **только** из жёстко заданных публичных сообщений
  собственного валидатора/адаптера и списка полей серверной JSON Schema.
  Сырые ответы модели, Markdown вакансии, произвольные ошибки, ключи и
  персональные записи не копируются в diagnostics.
- `error_code='invalid_output'` сохраняет прежний внешний контракт;
  `outputIssue` — только дополнительный безопасный атрибут ошибки.
- `outputIssue` не содержит данных о списании, числе попыток провайдера
  или допустимости повтора. `cost_usd IS NULL` и `reserved_usd > 0`
  означают неопределённость, а не нулевые расходы.
- При анализе использовать **read-only** локальные агрегаты, состояние
  `scheduler_attempts` и `/recoveryz`; не отправлять новый платный
  запрос ради проверки категории. Не изменять production-БД.

## Проверка без реальных запросов

`go test ./internal/parser -run '^TestExtractionOutputIssue' -count=1` —
unit тесты allowlist, неполного JSON, неверной схемы и запрета вывода
произвольного текста. Общие Go checks PR проверяют их в CI.
Интеграционные проверки AI-stage billing (включая cancellation, SIGKILL
и неопределённый COMMIT) — отдельно в disposable MariaDB CI.

Текущие категории не различают внутри `provider_response`
`refusal`, `length`, `empty` и `malformed envelope`: адаптер OpenAI
возвращает одинаковый фиксированный публичный код/сообщение. Если для
этих состояний нужна более точная диагностика, сделать отдельную
typed-error до слоя хранения, только с закрытым набором категорий и без
потери existing `invalid_output` контракта.
