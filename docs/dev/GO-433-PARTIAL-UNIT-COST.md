# GO-433. Первичная частичная стоимость новой вакансии

**Состояние:** реализована read-only *периодная* аналитика, **не** итоговый полный KPI acquisition cohort. Основывается на техаудите [GO-434](./GO-434-EXPENSE-AUDIT.md). Реальную сверку со счетами провайдеров и GO-436 пока не заменяет.

## Пользовательский интерфейс

Настройки → Парсинг вакансий → Диагностика → «Себестоимость новой вакансии».

Период: **последние 7 или 30 полных календарных дат, включая текущую неполную дату**, по часовому поясу **Europe/Moscow**. Фильтр: все источники или один из фактических `SourceOptions`, плюс `unknown`. Число новых вакансий = первые успешные операции `vacancy_import_operations.action='create'` с уникальным `vacancy_id`, подтверждённым существованием в `company_vacancies` и относящимся к парсеру (ручной ввод и Excel исключены). Повторные CREATE, UPDATE, UNCHANGED и failed не увеличивают счётчик. При одинаковом времени первого CREATE выбирается стабильный порядок по `id`. Если у первоначального CREATE дата не распознана, он не переносится на более поздний дубль, а помечается недатированным. При разных источниках одной основной карточки учитывается **источник первого CREATE**, а не каждая последующая ссылка.

Отображаются: **локально известная** стоимость Apify Actor и ИИ, неопределённые положительные резервы, операции с неизвестной ценой, конфликты чеков, наблюдаемые кредиты Firecrawl, количество новых карточек, дневная динамика и частичное отношение USD/вакансию.

## Как вычисляется числитель

- **Apify:** `apify_runs`, расход `charged_usd IS NOT NULL`, дедупликация по `account_id,run_id`; если Actor ID нет, только локальная операция `id`. Для одной группы с несовместимыми ценами сумма **не включается**, конфликт считается отдельно. Если `charged_usd IS NULL` — это неопределённый резерв, не оплаченный факт. Дата — первое `created_at` группы. Без доказанного lineage Actor → source **при выборе одного источника Apify полностью исключается из числителя**, UI показывает «Не распределено». Запрос не связывает Actor и dataset с вакансией по URL и не делает оплачиваемых POST.
- **ИИ:** `scheduler_attempts.id` (только `provider IN ('openai','openrouter')`), `cost_usd IS NOT NULL` есть локальная подтверждённая оценка, включая известный 0. `cost_usd=NULL, reserved_usd>0` — неопределённый резерв. `cost_usd=NULL, reserved_usd=0` — неизвестная стоимость, не бесплатная. Дата `started_at`. Фильтрация по записанному `source_id`, без JOIN на многие роли/кандидатов и без дублирования этапных `cost_usd`. Не учитываются неподключённые платные контуры и отдельные технические `openrouter_ai_logs` без USD.
- **Firecrawl:** сумма наблюдаемых `vacancy_raw_snapshots.firecrawl_credits` и число NULL/недостоверных кредитов. Это **не сумма денежных списаний и не самостоятельная квитанция по внешним API запросам**. Никакой конверсии в USD без исторического тарифа.
- Дополнительные расходы на безрезультатные поиски и ошибочные ИИ-вызовы остаются в календарном числителе, если соответствующая локальная сумма подтверждена. Никаких коэффициентов умножения на число кандидатов.
- Для периода **со всеми источниками** суммируются известные локальные Apify + AI расходы; при выборе конкретного источника суммируется только локально относимый AI, Apify показывается без attribution. Резервы, Stage receipts и технические логи **не добавляются** к USD.

## Как трактовать показатель

`partialPeriodRatioUsd = (локально известный Apify USD + локально известный ИИ USD) / число уникальных первых CREATE за тот же период`, только при положительном знаменателе **и наличии хотя бы одного ценового receipt**, в противном случае `null` («Нет значения»). При фильтре источника Apify исключён. Это **не полная цена создания вакансии**: расходы скана, классификации и поздней публикации могут относиться к разным когортам, а часть расхода не поддаётся денежной оценке. API отдаёт `calendarProxy=true`, `incompleteCosts=true`; UI явно называет значение *частичным календарным ориентиром*, не полным KPI.

Одно значение не следует сравнивать с тарифами подрядчиков или использовать для финрешений, пока не проведены сверка GO-434 по аккаунтам и lineage GO-436. При `newUniqueVacancies=0` выводить `partialPeriodRatioUsd=null`, но показывать расход.

## API и безопасность

`GET /api/scheduler/unit-cost?days=7|30&sourceId=all|<known>`. Требует действительной **администраторской сессии**. Незапрошенные/повторные параметры отклоняются (400), POST/мутации запрещены, ошибки SQL не раскрываются. Go использует только `SELECT` и `sql.TxOptions{ReadOnly:true,Isolation:sql.LevelRepeatableRead}`. В ответе только агрегаты и варианты фильтра, **нет идентификаторов аккаунтов, токенов, URL, резюме, текстов вакансий, названий работодателей или payload**.

Отдельная detached-компонента React получает новый endpoint; ни Worker, ни планировщик, ни схема БД, ни лимиты платных провайдеров не меняются.

## Границы и последующие PR

Сейчас нет произвольного диапазона дат: только 7/30 дней и независимый фильтр источника. Полная когортная модель потребует фиксируемого **сквозного идентификатора внешней операции и её связей** с scheduler scan, candidates и import, с поддержкой one-to-many без умножения суммы. Для Firecrawl нужно сохранять долларовую стоимость/тариф на дату и отдельное подтверждение провайдера, для Apify — учитывать Dataset GET и reconciliation. Исторический backfill запрещён без рассмотрения lineage.

Испытания: Go unit + HTTP security, реальная одноразовая MariaDB CI с несколькими receipts одного Actor, пустым оплачиваемым Actor, NULL reserve, нулём известной стоимости, пересечением источников у одной вакансии, поздним импортом, переходом московской полуночи, пустым знаменателем и проверкой неизменности DB. По окончании проверяются все три обязательных workflow на последнем HEAD.

**Нельзя закрывать GO-433 целиком** до подтверждённой полной когортной атрибуции, финансовой сверки и проверки UI на развёрнутом стенде. Этот PR — безопасная первая эксплуатационная ступень.
