## 3. Существенная находка и исправление в PR #518

У `DELETE /api/vacancies/{id}` linked-вакансии **два этапа**: первый переводит в архив, второй окончательно удаляет с отвязкой откликов/задач. Старый `VacancyActions` повторял DELETE после 503. Если первый COMMIT прошёл, а ответ потерян, повтор превращал операцию архивирования в hard-delete.

Исправление: после неизвестного исхода клиент сверяет свежий detail через `GET` без кэша; `404` означает уже удалено и повторный DELETE не нужен; смена `archived` относительно состояния, для которого был показан confirm, блокирует повтор до синхронизации списка и нового пользовательского подтверждения; при проверочном GET error удаление не повторяется. Go и схема не менялись.

Новые Playwright-mock кейсы на desktop/mobile: lost ACK после archive COMMIT; lost ACK после hard-delete COMMIT. Прежний кейс 503 до COMMIT остаётся. Никакая mock-сеть не является доказательством реального COMMIT в MariaDB.
