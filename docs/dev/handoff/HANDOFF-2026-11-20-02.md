## 3. Что обнаружено и исправлено

- #507: первоначальный staging CI нашёл 10 падений Playwright (5 desktop, 5 mobile): селектор `getByRole('button', {name: title})` совпадал с заголовком и с кнопкой пересчёта релевантности. Добавлено `exact: true`, затем CI полностью прошёл.
- #508: первоначальный отдельный прямой `npm run format:check` выявил 4 ранее существовавших файла с ненормализованным форматированием: `frontend/features/companies/CompanyDrawer.tsx`, `Filters.tsx`, `settings/ParserFunnel.tsx`, `settings/ParserHHScanSchedule.tsx`. В специализированном browser-workflow формат больше не проверяется повторно: сборка и браузерные сценарии обязательны, штатный GO-114 остаётся в `Public source security and Go checks`. **Открытый вопрос:** почему чистый прямой Prettier отличается от штатной последовательности `test-web-format-guard` → `format:check`; расследовать отдельно, не скрывать несоответствие и не переформатировать unrelated файлы попутно.
- #509: независимые тесты покрывают переключение карточки и текст роли при пустых полях; `S11-B04-19` всё ещё **частичен**, потому что полная очистка выбранных ролей в редакторе при пустом дереве не доказана. Архивная роль отображается как сохранённый путь, а новый выбор требует отдельной проверки.
- #510: раньше ссылку Telegram отрисовывали даже при отсутствующем `messageUrl`, а одинаковые URL источников повторялись. Новый `sources.ts` проверяет только абсолютный HTTP(S), сохраняет исходный полный `href`, использует нормализованный URL только для дедупликации. При отсутствии источников показывается пустое состояние.
- #510: `check-api-coverage.mjs` после добавления `sources.ts` ожидает **72** frontend TS/TSX вместо **71**. Списки транспортных вызовов не менялись (`157` sites, `7` JSX bindings, `1` forwarding, `75` dynamic URL); JSON и Markdown inventory обновлены. Финальный CI должен подтвердить это на head.
