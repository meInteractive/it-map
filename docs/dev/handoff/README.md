# Передачи дел IT-MAP

Эта папка — **единое место для последующих handoff-файлов** между чатами, Codex и сессиями разработки. Правило также закреплено в [AGENTS.md](../../../AGENTS.md), [задачах](../../../tasks/README.md) и [индексе документации](../README.md).

## Правила именования

- Для каждой передачи создавать **новый** Markdown-файл с датой: `HANDOFF-YYYY-MM-DD.md` (дата по Москве); при нескольких передачах в один день использовать `HANDOFF-YYYY-MM-DD-02.md`, `-03.md` и т. д. Не перезаписывать исторические снимки.
- **Свежие файлы ниже, старые — архивные.** Начинать с самого нового файла по имени, а затем сверять его с `main`, `tasks/SPRINT-01.md`, `tasks/SPRINT-01-PARSER-APIFY.md`, GitHub PR/CI и действующей конфигурацией. Handoff — не источник истины о runtime и не автоматическое разрешение на production.
- Структура каждой передачи: **(1)** файлы для входа в проект; **(2)** входящий контекст/инструкции Codex с очищением от приватного; **(3)** обнаруженные дефекты и гипотезы с явным уровнем доказанности; **(4)** исправления с PR/SHA/CI; **(5)** ближайшие задачи и критерии; **(6)** полезные материалы/ограничения; **(7)** что хранится только в приватном чате.
- **Публичный Git не использовать как хранилище приватных операционных данных:** не писать токены, пароли, SSH IP/ключи и host fingerprints, точные пути к временным приватным ключам/туннелям, зашифрованные значения, реальные резюме, SQL-выгрузки, личные данные, подробные счета провайдеров или скриншоты закрытых экранов. Для приватных деталей составлять отдельный текст **в чате пользователя**; не добавлять его в PR, issue, commit или тесты.
- Перед работой перепроверять соответствие фактов текущему коммиту, актуальность ссылок и права. Если старый handoff противоречит коду, зафиксировать несоответствие и проверить; не делать миграций/оплаченных вызовов на его основании.
