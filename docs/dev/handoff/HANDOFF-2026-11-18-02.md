## 3. Выводы и границы доказательств

- Уже существующий Go `funnel.go` создаёт `publicationWindow` с категориями `inWeek/older/future/undated` по first CREATE; UI и safe JSON умеют её показывать. Старый снимок без поля не устанавливает причину: несовпадение API/SPA или контракта экспорта **гипотезы**. PR #481 повышает видимость, **не** подтверждает причины реального расхождения «импорт vs публикация».
- В `reserveAttemptLocked` текущий guard связывает неизвестные платные AI-результаты по job и candidate+stage; нет общего durable полного input fingerprint для **разных** кандидатов. `reserved_usd=0,cost_usd=NULL` с провайдером — unknown, не доказанный ноль. PR #482 описывает будущий контракт без DDL.
- `publish.yml` сейчас собирает API `./cmd/itmap`; `receive_release.py` переключает и рестартует `itmap@main.service`. Отдельный worker unit использует самостоятельный путь и не обновляется обычным publish. Поэтому [GO-447](../../../tasks/GO-447-WORKER-DEPLOY-RESTART.md) остаётся операционным приоритетом Codex и требует same-SHA packaging, safe drain, rollback; **live deployment здесь не проводился**.
- Исторические GO-445/GO-446 требуют новой **разрешённой read-only** сверки runtime и ledger; старый HH cursor нельзя перезапускать с догаданными фильтрами. Никакого подключения к серверу в этом чате не было.
