# GO-113 — обязательная проверка TypeScript для React/Vite

**Срез:** 09.11.2026. Для самостоятельной Go/React/MariaDB версии IT Map. Этот PR не меняет бизнес-логику, API, рабочие данные, таймеры или production.

## Проблема

`npm run build:web` запускает Vite, который транспилирует TS/TSX, но **не проверяет все ошибки типов**. В `package.json` уже существовал `npm run typecheck` (`tsc --noEmit`), но его `tsconfig.json` рассчитан на смешанное legacy-приложение: Next/Vinext/Cloudflare, Go SPA и тестовую инфраструктуру. Такую команду нельзя незаметно объявить полноценной проверкой Go React SPA; изменение её поведения может нарушить старый проект.

## Граница проверки

Отдельный [`tsconfig.web.json`](../../tsconfig.web.json) наследует **`strict: true`** и **`noEmit: true`** и явно включает:

- `web/main.tsx` — используемая Vite точка входа;
- все `frontend/**/*.ts(x)` — включая lazy React-модули, API, навигацию и диагностику;
- `shared/**/*.ts` и `shared/**/*.d.mts` — реальные типы и контракты UI;
- `vite.web.config.ts` — конфигурация сборки.

Все импортированные TS/TSX-модули также проверяются по обычной транзитивной семантике TypeScript. Отдельный tsconfig не добавляет `@ts-ignore`, не снижает `strict`, не переключает проверку в `--noCheck` и не исключает используемые модули. Next-specific types/plugin не загружаются в отдельном Vite-проекте, а существующий общий `npm run typecheck` остаётся неизменным.

## Запуск и проверка

```bash
npm ci --no-audit --no-fund
node scripts/test-web-typecheck-guard.mjs
npm run typecheck:web
npm run build:web
```

**CI gate:** отдельный обязательный шаг в существующем `web` job [Go workflow](../../.github/workflows/go-ci.yml), после `npm ci` и до Vite. Ненулевой статус `tsc` останавливает работу job; существующие Go/MariaDB/браузерные проверки не ослабляются.

[Контрактный тест](../../scripts/test-web-typecheck-guard.mjs) подтверждает, что список исходников включает весь `frontend/` и используемые `shared/` и `web/` файлы, `strict/noEmit` активны, а шаг присутствует в workflow. На временном синтетическом файле настоящий TypeScript компилятор должен **упасть на присваивании числа строке (TS2322)** и успешно пройти после исправления. Никакие тестовые ошибки не коммитятся в исходный код.

## Критерии выпуска и ограничения

- На финальном HEAD новый `web` job проходит typecheck и Vite, Playwright проходит desktop/mobile, все три обязательных workflow имеют именно статус **success**.
- Синтетический негативный тест доказывает, что компилятор действительно обнаруживает ошибку и код CI не её подавляет.
- Если `tsc` выявит существующие ошибки в активном SPA, исправлять **источники ошибок**, не отключать строгость и не перекладывать проверки в неисполняемый конфиг. Конкретные дефекты фиксировать отдельно в отчёте PR.
- Общий legacy `npm run typecheck` не заменяется: сквозную legacy-проверку можно рассматривать отдельной задачей после завершения миграции.
- GO-113 всё ещё относится к инженерной стабилизации спринта 1.2; релизный gate спринта 1.1 и изменения схемы MariaDB остаются отдельной компетенцией Codex.

Точные номера PR, SHA и результаты GitHub CI фиксируются в [handoff](handoff/HANDOFF-2026-11-09.md) после выполнения.
