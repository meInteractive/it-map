# GO-364: SQL-стадия структурирования вакансии

`ExtractionStageStore` подключает `extract_vacancy` к существующему `AIStageExecutor`. В owned транзакции проверяются активный источник и область владельца, текущий заголовок и хотя бы одно актуальное match-решение корневой роли, публичный URL вакансии и последний валидный снимок. Промт/модель читаются из существующих настроек без bootstrap или DDL; хеши промта и конфигурации совпадают с source. Пустая строка настроенного промта не заменяется значением по умолчанию.

Успешный кэш используется только для того же кандидата, снимка, модели, промта и schema v2; его данные повторно проверяются. Неоднозначное одинаковое время последних записей или повреждённый кэш не выбираются наугад. Новый запрос содержит полный Markdown и обязательную схему, проходит existing Attempt billing и выполняется вне SQL транзакции. Два LLM slots и candidate lease берутся в таблице vacancy_detail_leases: slot не перехватывается после смены поколения до истечения срока. При network/timeout и неизвестной стоимости блокировки и денежный резерв сохраняются до безопасного восстановления.

Перед отправкой и записью повторно проверяются кандидат, владельцы, избранное, роли, снимок, настройки и непросроченные lease. Нормализованные данные, source diagnostics, стоимость/токены и завершение attempt/job фиксируются одной транзакцией. Invalid output, исчерпанный бюджет, пустой промт и слишком длинный текст создают failure receipt без ложного успеха; два последних случая не посылают POST и не занимают LLM slot. Если generator отсутствует или attempt уже существует, только что полученные lease снимаются без вызова провайдера.

Семь actual `extractCandidateMarkdown` сценариев в SQLite :memory: сравниваются с Go/MariaDB: сохранённые поля, provenance hashes, diagnostics, ошибки и исправления. Required isolated MariaDB gate дополнительно проверяет cache без нового POST, бюджет, неопределённый исход, изменение промта, slot limits и очистку после незапущенного attempt. URL и usage estimates сверяются с actual source на23 синтетических случаях. Локальный guarded SQL skip не является SQL-приёмкой.

Это одна стадия: automatic enqueue следующей задачи, SQL-стадия конечных ролей, импорт, релевантность и scheduler tick остаются открытыми. Main runtime/очередь здесь не активируются; реальная база, секреты, provider POST и сервер не затронуты.
