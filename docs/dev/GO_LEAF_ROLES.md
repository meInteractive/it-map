# GO-365: запрос и проверка конечных ролей

`ValidateLeafRoleIDs` сохраняет source-контракт: JSON-объект содержит только role_ids, все значения — безопасные целые ID из разрешённого списка, без повторов и не более12. Результат сортируется. Некорректный JSON и нарушение состава ролей возвращают разные исходные ошибки.

`PrepareLeafRoleRequest` формирует запрос к OpenAI/бесплатной OpenRouter модели с теми же schema и сообщениями либо типизированный Decisions запрос JEV. Полный Markdown не усекается; отсутствие разрешённых ролей, пустой промт и текст более120000 UTF-16 units останавливают запрос до обращения к модели. Для JEV и обычных моделей проверка возвращает конкретную ошибку без повторного POST.

Actual `validateLeafRoleIds` даёт15 source cases. Четыре сценария исполняют `analyzeVacancyLeafRoles` на SQLite :memory: с синтетическим снимком и mock provider и сравнивают OpenAI messages/schema, JEV state/roles и ошибки. Отдельные mock tests проверяют обработку validator error и единичный POST. Локальные тесты и required source CI не подключают реальную БД или провайдеров.

Эта порция подготавливает запрос и валидирует ответ. SQL stage выбора ролей, provenance/cache/leases и handoff выделены в GO-366. Worker и сервер не активируются.
