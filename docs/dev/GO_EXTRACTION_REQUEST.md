# GO-361: подготовка запроса извлечения вакансии

`PrepareExtractionRequest` формирует задачу `vacancy_extraction` с source schema v2, пределом32768 output tokens и двумя сообщениями. Полный Markdown, название, компания и URL сериализуются в user message как данные; системный промт и точная компактная схема сохраняют поведение прежнего сервиса. Длинный Markdown более120000 UTF-16 units и пустой промт отклоняются до вызова модели без усечения.

`ValidateContent` подключает `NormalizeExtraction` к `Generator.Automatic`. Конкретная ошибка проверки возвращается вызывающей стадии для OpenAI и структурированного OpenRouter; при неправильном ответе платный вызов не повторяется. Необязательные неподтверждённые поля допускаются к последующей нормализации, а неподтверждённая сумма зарплаты и повреждённый ответ отклоняются.

Actual `extractCandidateMarkdown` исполняется в SQLite :memory: с synthetic fixtures и подставными HTTP ответами. Семь исходных сценариев проверяют два сообщения и JSON Schema, корректировки, ошибку зарплаты, пустой промт, лимит текста, специальные HTML/Unicode символы и UTF-16 длину emoji. Отдельный mock тест подтверждает сохранение ошибки и один вызов для обоих провайдеров. Все сетевые запросы в тестах подменены.

Это подготовка запроса, которая может передаваться в уже существующий executor; concrete SQL repository полного текста, cache, provenance, lease и сохранение extraction выполняются следующей задачей GO-362. Рабочая очередь и сервер этой веткой не запускаются.
