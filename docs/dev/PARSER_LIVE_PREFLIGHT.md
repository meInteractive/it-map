# GO-407: подготовка ограниченной проверки настоящего Apify

## Подтверждённые границы

Владелец подтвердил месячные лимиты: Apify — 5 USD, OpenRouter — 10 USD,
OpenAI — 10 USD. Разрешённый источник для проверки — работодатель
`https://hh.ru/employer/780654`. Текущий HH adapter преобразует ссылку на
работодателя в запрос поиска по тому же `employer_id`, первую страницу,
до 100 результатов; это не ограничение одной вакансиной.

Сквозной mock на отдельной MariaDB уже проверен в GO-406. Реальный Actor,
реальные AI-вызовы и импорт реальных вакансий в этом пункте ещё не выполнялись.
При запуске использовать отдельную staging-БД, один явно разрешённый источник,
ручной сигнал, ограниченное число стадий и сохранение run ID и расходов;
автоматическое расписание и рабочие автоматизации не включать.

## Ключи и учёт расходов

В существующем сайте обнаружены непустые зашифрованные записи OpenAI,
OpenRouter и бесплатного профиля Apify; OpenRouter сообщает `connected`.
Значения ключей не выводились и не копировались. Секрет шифрования сайта
доступен его runtime как secret, но не выдаётся через доступный интерфейс
настройки Sites. Поэтому наличие записей не подтверждает возможность
использовать их из независимого Go staging: потребуется безопасный способ
передать существующие ключи в его настройки без раскрытия в чате или логах.

Месячные суммы относятся к каждому аккаунту провайдера, включая существующий
сайт и другие клиенты. Локальный журнал staging отражает только его операции;
общий месячный лимит планировщика не доказывает соблюдения отдельных лимитов
OpenRouter и OpenAI по всему аккаунту. Apify дополнительно учитывает данные
аккаунта провайдера и собственные резервы. Перед платным запуском необходимо
подтвердить текущий остаток и действующие ограничения непосредственно на каждом
аккаунте; если это невозможно подтвердить, запуск блокируется. Не переносить
реальные пользовательские данные и не использовать фиктивные расходы GO-406
как фактический остаток.

После разрешённого запуска проверить статус Actor, стоимость и ошибки, импорт,
API/SQL readback, повтор и восстановление. Не повторять неизвестный платный
запрос вслепую. Фиксировать только безопасные идентификаторы и результаты,
без ключей, персональных данных и содержимого пользовательских вакансий.
