## Что не подтверждено

GitHub REST API (`gh api repos/meInteractive/it-map` и Actions API) возвращает `Forbidden`. Нельзя подтвердить branch protection, API-права на PR, существующие PR, запуски/логи Actions или создать PR без рабочего доступа. Git HEAD/default branch проверены отдельно по Git-протоколу. Доступ чтения Git не означает доступ API или push.

MariaDB 10.11 не запускалась локально: разрешение задачи ограничено одноразовой синтетической БД внутри CI. Существующий workflow проверен статически: контейнер 10.11, schema-only импорт, read-only пользователь приложения, отдельный writer, UUID поколения до записи, обязательные DSN, проверка metadata/FK/trigger/InnoDB, rollback/clientFoundRows, синтетический seed только после пустых SQL-тестов и авторизованный Go/API smoke. Фактическое выполнение и SQL-поведение должны быть проверены на GitHub Actions. Название «staging gate» не означает внешний deployment.

Внешний staging-домен, HTTPS/Secure cookie в браузере, PWA/мобильная версия и пользовательский снимок не проверялись. Production, реальные БД, D1, Sites automation и платные API не затрагивались. Полнота API не доказана; его реализация не менялась.

## Исправление порядка SQL-тестов PR №1

По отдельному поручению пользователя исправлен отказ run `40127890410` для PR #1. API подтвердил точный SHA `202328f`, падение шага SQL-тестов и пропуск последующего seed/API smoke. В текущем сеансе GitHub API доступен; загрузка полного архива логов с results-receiver.actions.githubusercontent.com возвращает Forbidden. SQL-причины проверены по исходникам и порядку workflow:

- `applications.Repository.CRM`: `read(..., withCatalog=true)` сначала читает отклики/историю (нулевое число строк допустимо), затем `QueryRow(SELECT data_json FROM app_catalog WHERE id=1).Scan(...)` возвращает `sql.ErrNoRows`.
- `tasks.Repository.List`: тот же `QueryRow` выполняется первым, до чтения `company_tasks`; отсутствует каталог, а не задача пользователя.
- `vacancies.Repository.List`: пустой справочник ролей читается успешно, затем тот же `QueryRow` завершается `sql.ErrNoRows` до CTE списков вакансий.

Схема не содержит строк; `smoke-catalog.sql` раньше загружался только после этих запросов. Это ошибка предусловий/порядка CI, а не подключения MariaDB или обязательности личных записей Eugene. Возвращать успешный пустой ответ при любой SQL-ошибке нельзя. Исторический JS `readAppCatalog` использует встроенный seed при отсутствии каталога; Go намеренно не инициализирует данные на GET и требует явно подготовленную БД. Импорт fallback-каталога из старого Sites в Go не добавлен. Контракты чтения списков, not-found и отсутствие личных/необязательных записей проверяются на синтетических данных, production-код не изменён.

Новый порядок: все `internal/storage` тесты на пустой схеме → исходные три строки `smoke-catalog.sql` → четыре строки `read-models.sql` → все остальные `internal` пакеты → сборка tagged-бинарника → существующий авторизованный Go/MariaDB/API smoke. Writer DSN и UUID доступны только storage-фазе; бизнес-тестам выдан SELECT-only DSN. Ни один пакет не исключён из полного набора: storage проверяется отдельной первой фазой. `continue-on-error` и ослабление SQL-проверок не добавлены.

Минимальная дополнительная фикстура: одна общая вакансия, один синтетический отклик Eugene, одна строка его истории и одна задача Eugene. Demo намеренно без личных строк. Существующий safety gate разрешает только четыре точных INSERT, без реальных URL/контактов/содержимого. Усилены проверки количества/связей/истории/NULL и изоляции Eugene/Demo. Все шесть бизнес-интеграционных тестов в обязательном CI-режиме завершаются ошибкой при отсутствии DSN/требуемых строк, а не пропуском.

Локально выполнены `go mod verify`, `go mod tidy -diff`, vet (обычный и tagged), race-тесты, tagged-тесты/сборка, static source/schema/seed gates, staging smoke unit-test, actionlint и bash-синтаксис/order workflow. Без локального DSN живые тесты в обычном режиме не выполняются; отдельная отрицательная проверка обязательного режима требует шесть failures и ноль skips. Safety gate отдельно отклоняет посторонний текст, дополнительный DELETE и смену владельца в фикстуре. Live SQL и авторизованный API проверяются новым Actions run после отправки этой порции в существующую ветку PR #1; фактический результат сообщается отдельно. GO-005/007 не закрыты, внешний staging и реальные данные не затрагиваются.
