# Фильтр HH по профессиональным ролям: план реализации

Обновлено 5 ноября 2026 года по прямому решению пользователя. Для новых поисков HH применяются только профессиональные роли HH, выбранные вручную; фильтр по названию и списки поисковых слов не нужны. Для каждой крупной роли IT-MAP (например, IT Manager, Журналист) настройки независимы. ИИ-классификация остаётся последующим этапом и не подменяет фильтр HH.

## Проверенные факты

Публичный `GET https://api.hh.ru/professional_roles` возвращает категории с вложенными ролями; один ID роли может встречаться в разных категориях. Снимок от 05.11.2026: 27 категорий, 304 вхождения, 194 уникальных ID. Источники и ограничения: [исследование](HH_PROFESSIONAL_ROLES_RESEARCH.md). Выбор в разных ветках для одного ID должен отображаться синхронно. Человеческий выбор ID обязателен: автоматически предполагать соответствия нельзя.

HH документирует повторяющийся параметр `professional_role` в поиске вакансий. Используемый Actor принимает `startUrl`, но пока не доказано, что он действительно сохраняет и применяет этот параметр. Проверять фактический отбор ограниченным запуском только после подготовки всех частей; получение правильного INPUT само по себе не подтверждает фильтрацию результата.

## Порядок реализации

1. **GO-423 — создание безопасного INPUT.** При явном списке ID формировать повторяющиеся `professional_role`, убирать текстовый поиск и старые значения роли из исходного URL, сохранять ограничения работодателя, Москвы и даты. Отклонять пустой/некорректный список и несовместимость с фильтром названия. `nil` означает старый режим для воспроизведения оплаченного INPUT; сам по себе этот шаг действующий парсер не переключает. Покрыть unit-тестами и обеспечить совместимость старых входов.
2. **GO-424 — справочник и настройки по направлениям.** Сделать доступную администратору загрузку дерева и настройку независимо для каждого корневого направления. Одинаковые ID во всех категориях — один выбор для данного направления. Сохранять именно ID, версии и название/состояние для диагностики устаревших значений; текущий HH-справочник способен измениться. Дать понятный способ обновить справочник и обработать недоступность HH, не стирая сохранённый выбор. У каждой крупной роли собственное множество; настройка IT Manager не меняет настройку журналиста. Новую схему БД оформить отдельной версионированной миграцией, проверить в одноразовой MariaDB, предусмотреть ревизии и CAS. Рабочая MariaDB и DDL — только после отдельного согласования согласно AGENTS.md. Текущий `GET /api/classification/settings` нового Go-приложения возвращал 503, поэтому не предполагать доступность старого интерфейса; решить расположение настройки и контракт независимо или восстановить необходимую часть API.
3. **GO-425 — применение в парсере.** Вычислять объединение выбранных HH ID всех активных корневых направлений, отсортировать и убрать дубли. Пустой или некорректный набор хотя бы для одного активного направления должен явно остановить новый платный Actor с понятной диагностикой, а не незаметно расширить поиск. Сохранять снимок ID и его идентичность в cursor/операции; при изменении настроек не запускать автоматически новую страницу с другими параметрами. Уже оплаченный Actor должен дочитываться с исходным INPUT, без повторного платного вызова; отдельно проверить сценарий возобновления после смены ревизии источника. Сохранять старый формат cursor и прежний путь его воспроизведения. Для новых списков полностью исключить `text`, в том числе из исходного URL. Ограничения Москва/даты/работодатель и семантическая классификация сохраняются.
4. **Проверка:** unit и контрактные тесты, изолированная MariaDB для сохранения, ревизий и старых cursor, браузерные desktop/mobile проверки настройки, CI на точном SHA. После согласования и применения необходимых миграций — один ограниченный тест реального Actor по разрешённому пользователем бюджету Apify до $5/месяц, предварительно проверить фактический остаток/резерв. Проверять не только INPUT, но и полученные вакансии и их роли HH; зафиксировать ограничения подтверждения. Не запускать глобальную очередь и не повторять сомнительный платный вызов.

## Важные ограничения

Роль HH — разметка HH, а не гарантия принадлежности к IT или журналистике. Например, «Руководитель проектов» с одним ID встречается в нескольких категориях. Поэтому выбор вручную и последующая ИИ-классификация важны; вакансии с неверной или отсутствующей разметкой могут не попасть в выборку. Существующий пользовательский промпт и названия направлений автоматически не переводятся в HH ID.

Отложенный вариант поиска по названиям и временный список IT Manager сохранены в [отдельном черновике](HH_TITLE_FILTER_DEFERRED.md), задача GO-426.
