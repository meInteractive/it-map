# GO-368: передача кандидата следующей стадии

Необязательный CandidateHandoff сохраняет результат стадии, создаёт следующее задание и завершает текущее в одной транзакции. Проверяются владелец, источник, кандидат, тип и ключ задания; существующее задание с тем же ключом повторно используется только при совпадении его содержимого. При ошибке транзакция откатывается, а уже начатый запрос к провайдеру автоматически повторно не отправляется.

Следующая стадия должна вычисляться серверным планировщиком заново из проверенных данных в той же транзакции. Сам SQL-планировщик и подключение к работающему worker ещё не реализованы. Новая возможность не активирует парсер и не выполняет запросы к провайдерам.

Тест CandidateHandoffDisposable предназначен для изолированной MariaDB в GitHub CI: он проверяет согласованность записи и очереди, повторное использование задания, кеш, откат, границу владельца и неопределённый ответ провайдера. В обычной локальной среде этот тест пропускается; его успешное выполнение в CI необходимо для подтверждения работы с MariaDB.
