# Профессиональные роли HH: предварительное исследование

Проверено 5 ноября 2026 года. Публичный запрос `GET https://api.hh.ru/professional_roles` с заголовками клиента вернул HTTP 200 и справочник категорий с вложенными ролями. В полученном снимке 27 категорий, 304 включения ролей и 194 уникальных ID. Справочник может изменяться; эти числа не являются контрактом.

Одна и та же роль встречается в нескольких ветвях. Например, ID `107` «Руководитель проектов» присутствует в IT, строительстве и консалтинге. Выбор категории как области интерфейса не означает отдельного ID роли и не доказывает, что все вакансии этой роли относятся к IT. В категории IT также присутствуют, например, ID `36` «Директор по информационным технологиям (CIO)», `73` «Менеджер продукта» и `104` «Руководитель группы разработки». Это примеры справочника, а не утверждённое сопоставление пользовательских направлений.

[Документация HH](https://api.hh.ru/openapi/redoc) описывает справочник и параметр поиска вакансий `professional_role`, допускающий несколько значений. В [документации используемого Actor](https://apify.com/shahidirfan/hh-ru-job-scraper) отдельное поле `professional_role` не заявлено; Actor принимает URL поиска через `startUrl`, который имеет приоритет над отдельными полями поиска. Применение параметра профессиональной роли внутри этого URL самим Actor пока не проверено. Нужно подтвердить его на синтетическом и затем ограниченном реальном запуске; наличие параметра в INPUT само по себе не доказывает отбор результатов.

Следующая задача GO-424: получать и обновлять справочник, показывать дерево и сохранять выбранные пользователем ID отдельно для каждой нашей корневой роли. Нужны проверка отсутствующих/устаревших ролей, явное поведение при недоступности справочника, совместимость существующих настроек и защита оплаченных запусков от незаметной смены input. По поручению пользователя поиск по названиям для новых выборок не применяется. Фильтр зависит от разметки вакансии на стороне HH; перед включением необходимо сравнить выборку и предусмотреть понятную диагностику. Автоматическое назначение ID по имени нашей роли не предполагается.
