# GO-119 — проверяемая карта архитектуры IT Map

**Срез исходников:** 09.11.2026, `main` на SHA [7fa1047](https://github.com/meInteractive/it-map/commit/7fa1047860df0a92165726c438418f77a4b43909) (после merge PR #292). Следующие PR/CI могут изменить этот срез: перед применением Codex обязан проверить актуальный `main`.

**Назначение:** короткий технический ориентир для нового разработчика и Codex. Исторический план, синтетический CI, ограниченная staging-приёмка и наблюдение владельца за работающим пилотом — **разные уровни доказательств**. Ни один из них не означает, что Go-версия принята как production-ready или что D1 полностью заменена MariaDB.

## Три конкретных инженерных решения

**1. Платный HH Actor и устойчивость к повторам.** Состояние источника, Actor/операции и кандидатов хранится в MariaDB. Отдельные этапы старта, чтения dataset и обработки кандидатов препятствуют слепому повтору платного запуска при потере ответа. Результат неизвестного платного вызова не трактуется как нулевая стоимость. Доказательства: [код парсера](../../internal/parser/), [BILLING.md](../../internal/parser/BILLING.md), [GO-434 аудит](GO-434-EXPENSE-AUDIT.md). Никаких измеренных показателей снижения стоимости или p95 здесь не заявляется.

**2. Разница даты публикации и даты импорта.** В [PR #287](https://github.com/meInteractive/it-map/pull/287) исправлен показатель, который исторически смешивал успешный импорт кандидатов и создание уникальных карточек. Для HH дополнительно выявлен риск разрыва дат при 7-дневном интервале и 3-дневном окне; последующие успешные проверки не являются автоматической исторической догрузкой. Следующая проверка покрытий — [issue #293](https://github.com/meInteractive/it-map/issues/293). Не менять сохранённые сроки/окна и не запускать оплаченный backfill без допуска.

**3. Доказательность себестоимости.** Локальные подтверждённые суммы, зарезервированные расходы с неизвестным исходом и Firecrawl-кредиты — разные величины. GO-433 выводит **частичный** календарный показатель, а не полноценную цену всей когорты. Для истинного provider→candidate→vacancy lineage потребуется проектирование и миграция под контролем Codex; описание в [дизайн-документе](GO-433-PROVIDER-COHORT-LINEAGE-DESIGN.md). PR #286 содержит контракт и тесты, **не DDL**.

## Доказательства и release gate

- **Код:** исходники и привязка сервисов в [main.go](../../cmd/itmap/main.go), зарегистрированные маршруты в [handler.go](../../internal/httpapi/handler.go). `go.mod` объявляет Go 1.23.0 как минимальную версию модуля; версия установленного toolchain — отдельный факт, не следует из этой строки.
- **Автотесты на конкретном SHA:** [PR #292](https://github.com/meInteractive/it-map/pull/292), head `b8235484c3e3cb24d26588bf770719400fd5c0a3`: 3 mandatory workflow завершились успешно, 17/17 check runs. Аналогичная проверка 17/17 на PR [#289](https://github.com/meInteractive/it-map/pull/289) (head `0089ebf40989fe137541c8953a15ba5fd213515d`) и [#291](https://github.com/meInteractive/it-map/pull/291) (head `c2fbbe4522f058e9cb294dc03da8992e53e05589`). Это **вердикт CI этих PR**, а не новая проверка всех интеграций на текущем production.
- **Контролируемый staging:** ограниченные исторические проверки [GO-406](PARSER_STAGING_PREFLIGHT.md) / [GO-407](PARSER_LIVE_PREFLIGHT.md), относящиеся к конкретным сборкам и условиям, **не ко всем поздним PR**.
- **Операторское наблюдение:** приватная диагностика владельца от 09.11 подтверждает возобновление HH-пайплайна после изменения интервала и появление новой карточки. Сырой JSON, финансовые данные, идентификаторы компаний/заданий в публичный репозиторий **не переносить**. [Incident #290](https://github.com/meInteractive/it-map/issues/290) закрыт, исторические пробелы изучаются отдельно.
- **Не принято:** полный cutover D1→MariaDB и возврат, миграция реальных данных, разрешение `APP_ENV=production`, `GET /health/ready`, все legacy API, полный пул источников, RabbitMQ/outbox, полноценный непрерывный Go Worker, реальная сверка счетов, полная когортная себестоимость. Ничего из этого не следует автоматически из зелёного CI.

## Короткий маршрут следующему инженеру

1. Прочитать [AGENTS.md](../../AGENTS.md), [ARCHITECTURE.md](ARCHITECTURE.md), [активный handoff](handoff/HANDOFF-2026-11-09.md) и [спринты](../../tasks/README.md).
2. Для заявленного endpoint проверить его регистрацию в [handler.go](../../internal/httpapi/handler.go), подключение в [main.go](../../cmd/itmap/main.go), Go repository, React caller и соответствующий test.
3. Перед кодом сверить HEAD `main` и три обязательных GitHub Actions workflow на текущем PR SHA; не использовать зелёный CI старого PR как доказательство текущего.
4. Любые DDL, фактическое состояние production MariaDB, миграции, бюджеты, включение worker, реальные Apify/ИИ вызовы и backfill — только через отдельный план Codex, согласование владельца и контроль восстановления. **GO-119 меняет документацию, а не работающую систему.**
