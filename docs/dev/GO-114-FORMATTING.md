# GO-114 — форматирование поддерживаемого TypeScript

**Этап 1 (09.11.2026).** Введён один зафиксированный инструмент: Prettier 3.6.2; общие параметры в [`.prettierrc.json`](../../.prettierrc.json). Действующий JS/Next/D1-код `server/`, `app/`, `build/`, generated и исторические источники-эталоны **не форматируются**.

## Область

- `frontend/**/*.ts`, `frontend/**/*.tsx`;
- `shared/**/*.ts`, `shared/**/*.tsx`, `shared/**/*.mts`;
- `web/main.tsx` и `vite.web.config.ts`.

На первом этапе действует **переходный baseline**: весь давно существующий фронтенд пока не переформатирован. Проверяются **все новые и изменённые** поддерживаемые файлы относительно базы PR/последнего push, включая добавленные файлы. Изменённый старый файл форматируется целиком. Это не выборочная проверка строк и не разрешение оставлять новые файлы без проверки. При отсутствии изменений в поддерживаемой области команда выдаёт явное сообщение; это **не означает**, что весь исторический фронтенд уже соответствует Prettier.

## Команды

```bash
npm ci --no-audit --no-fund
npm run format             # форматирование новых/изменённых поддерживаемых файлов
npm run format:check       # проверка тех же файлов без записи
node scripts/test-web-format-guard.mjs
npm run typecheck:web
npm run build:web
```

Выбор файлов делает `scripts/format-web.mjs` по `git diff` относительно основания события GitHub PR или push и с учётом незакоммиченных файлов. В CI web job выполняется checkout полной истории, и если основание diff отсутствует, проверка должна **провалиться**, а не сообщить об успехе. Для локального checkout без базовой ветки команда проверяет незакоммиченные изменения; разработчику необходимо иметь `origin/main` для проверки уже закоммиченных изменений.

## Доказательства / ограничения

- `scripts/test-web-format-guard.mjs` создаёт только временный синтетический `.ts` в `frontend/`, проверяет отказ для неправильного форматирования, исправление, повторный успешный check и идемпотентный второй write, затем удаляет файл.
- CI gate запускается после `npm ci` перед TS/Vite. Остальные workflows не отключаются.
- **Этап 2 GO-114 не выполнен:** отдельный механический коммит форматирования полного согласованного объёма, повторное typecheck/build/браузерное тестирование и перевод CI на `--check` по всей поддерживаемой области. Не закрывать GO-114 до этого этапа.
- Изменение стиля не является разрешением на GO-115 (рефакторинг Application/cache), новую схему БД, production или платные провайдеры.
