# Поддержка документации

Текущие правила разработки задаются [AGENTS.md](../../AGENTS.md), порядок работы —
[PLANS.md](../../PLANS.md), результаты проверок — [tasks/STACK.md](../../tasks/STACK.md).

## Где хранить материалы

- `docs/user/` — руководства и справочники, которые читает пользователь. Инструкции установки находятся в `docs/user/deployment/`.
- `docs/dev/` — архитектура, решения, контракты переноса, проверки и отчёты разработки.
- `docs/dev/archive/` — явно обозначенные исторические инструкции.

Материалы существующих разделов приложения перечислены в
[пользовательском манифесте](../user/manifest.json). `file` содержит имя Markdown
без каталогов: оно используется в метаданных API и имени скачиваемого файла.
Идентификаторы разделов и адреса `/api/docs/<id>` не зависят от расположения
исходников в репозитории.

## Как обновлять

1. Исправьте исходный документ в соответствующей папке. Новые комментарии к коду пишите на русском.
2. Для пользовательских изменений обновите `revision` и `updatedAt` манифеста и [журнал изменений](../user/CHANGELOG.md). Версии API, схемы и форматов не повышаются из-за перемещения документов.
3. Запустите `node scripts/prepare-server.mjs`: генератор читает пользовательские документы, сверяет версии контрактов и обновляет автоматические таблицы. В Go-ветке источник SQL — принятый снимок `internal/v39/schema.json`; при наличии истории Drizzle таблицы строятся в изолированной SQLite. Рабочая БД не используется.
4. Автоблоки `AUTO` и `server/generated/documentation.json` не правьте вручную. Сведения о резервных копиях берутся из [BACKUP_FORMAT.md](../user/BACKUP_FORMAT.md).
5. Проверьте локальные ссылки, `node scripts/test-documentation.mjs`, сборку `npm run build:web` и обязательные проверки проекта. Обновите `SHA256SUMS` после генерации.

Перенос файла требует обновления Markdown-ссылок, путей в генераторах, тестах,
проверках CI и инструкциях. Ссылки между разделами приложения сохраняют имена
пользовательских файлов; ссылки на материалы разработчика должны открывать
соответствующий файл репозитория.

Исторический порядок работы с GPT Sites сохранён
[отдельно](archive/MAINTENANCE-SITES.md). Он не заменяет действующие правила Go
и не разрешает автоматическое слияние, развёртывание или доступ к рабочим данным.
