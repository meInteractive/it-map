# GO-006: React в браузере поверх Go и синтетической MariaDB

Проверка запускается в существующем `mariadb-staging-ci.yml` после storage-тестов и загрузки утверждённых `smoke-catalog.sql`/`read-models.sql`. До загрузки данных по-прежнему проверяются пустая схема, rollback и конкурирующие блокировки. Приложение работает с SELECT-only пользователем одноразовой БД `itmap_ci`; рабочие базы и старый Sites не используются.

Node.js 24 и `npm ci` устанавливают зависимости по lockfile. Версия `@playwright/test` закреплена; команда `npx playwright install --with-deps --only-shell chromium` устанавливает соответствующий headless Chromium на CI runner. После `npm run build:web` Go получает `WEB_DIST_DIR`, указывающий только на `dist/web`. В том же жизненном цикле сервера выполняются существующий SQL/API smoke и `npm run test:browser`. Ошибка браузерного сценария проваливает job; retries, пропусков и `continue-on-error` нет.

## Четыре обязательных сценария

На настольном viewport 1280×800 и мобильном 390×844 выполняются по две проверки:

1. Настоящая React-страница входа на SPA deep link: форма видима, CSS применился, нет горизонтального переполнения страницы входа; анонимный `/api/session` возвращает 401; отсутствующий JS — 404; manifest и обе иконки доступны.
2. Вход через браузерную форму (`POST /auth=303`), чтение сессии и свойств HttpOnly/Secure/SameSite cookie; видимость синтетической задачи и связанной вакансии; переход в список компаний и вакансий; выход через `/logout`, возврат формы и 401 для сессии. Данные берутся из настоящих Go/MariaDB запросов, без mock API.

Каждый сценарий использует новый browser context. Неперехваченные исключения JavaScript приводят к ошибке. Внешние запросы запрещены и также проваливают проверку. Вход разрешён только на HTTP loopback, с явно указанным синтетическим паролем `ITMAP_SMOKE_PASSWORD`. Трассы, видео, screenshots и сохранение auth state отключены; временные файлы тестов находятся в `RUNNER_TEMP` или `/tmp`, вне checkout.

## Локальное воспроизведение

Для полной проверки нужны уже работающий Go и безопасная синтетическая БД, создаваемая внутри CI. Не направлять тест на внешний staging, реальные данные или существующий локальный production. В обычной облачной разработке без MariaDB отдельно проверяется только страница входа:

```bash
cd /workspace/it-map
npm ci
npm run build:web
# Запустить Go из этого checkout с development, DB_ENABLED=false,
# AUTH_ENABLED=true, только синтетическими auth-значениями,
# HTTP_ADDR=127.0.0.1:18082 и WEB_DIST_DIR=/workspace/it-map/dist/web.
ITMAP_BROWSER_URL=http://127.0.0.1:18082 \
ITMAP_BROWSER_EXECUTABLE=/usr/bin/chromium \
npm run test:browser -- --grep 'страница входа'
```

`ITMAP_BROWSER_EXECUTABLE` необязателен: локально позволяет использовать установленный Chromium; в CI используется браузер закреплённой версии Playwright. Без установленного системного браузера сначала установить браузер командой Playwright, сохраняя TLS-проверку. `ITMAP_BROWSER_URL` отвергает внешний хост, HTTPS, user info, query/hash и нестандартный базовый путь до запуска браузера. Пустой пароль не приводит к skip: авторизованный сценарий завершается ошибкой.

## Границы приёмки

Это обязательная проверка базового сценария на двух размерах экрана, а не полная приёмка всех экранов и PWA. Не проверены установка/offline PWA, карта с внешними tiles, Safari/Firefox, все роли, изменяющие CRM-операции и пользовательский снимок. Существующий `/api/google-calendar/status` пока возвращает 503: календарь не подменяется mock-ответом и не подключается, чтение задач проверяется независимо. Свойство Secure cookie проверяется на доверенном Chromium loopback; это не подтверждение работы HTTPS reverse proxy и cookie на внешнем staging-домене. Readiness остаётся закрытой до cutover.

GO-006/GO-007 остаются открытыми. После ручной проверки этого PR следующая часть GO-006 — расширение браузерной приёмки по остальным существующим сценариям; внешний staging и тест согласованного снимка требуют отдельного разрешения и безопасной конфигурации.
