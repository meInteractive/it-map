# Размещение, релизы и откат

## Действующая схема ADR-028

До завершения спринта1.1 на временном сервере работает **только main**, staging.
Нет второго dev-процесса и автоматической доставки произвольных feature-веток.
После приёмки main переносится на отдельный основной сервер; на временном остаётся
конкретная ветка спринта1.2. Адрес основного сервера, дата и имя ветки ещё не заданы.

На разных серверах независимы MariaDB, SQL-users/базы/пароли, runtime env,
SESSION_SECRET, административные и deploy-доступы. DB_HOST=127.0.0.1 может совпадать
текстом, поскольку экземпляры физически разные. Development не получает права
к стабильной БД, автоматической синхронизации нет. ADR-019 отменено, история
сохранена в [DECISIONS.md](../../dev/DECISIONS.md).

## Проверенный релиз

Выбрать актуальный main SHA и проверить ancestry/фактические файлы. MERGED у
дочернего PR недостаточно. Go бинарник с mariadb tag и web — одного SHA,
архитектура соответствует target; зависимости pinned. Не собирать из dirty tree.

Первая установка — [SERVER.md](SERVER.md): root-owned releases/<SHA>, current,
EnvironmentFile вне релизов, отдельный runtime. Обновления — существующий
[forced-command receiver](RECEIVER.md), не произвольный SSH shell или root-key.

[Actions](ACTIONS.md) регистрирует main-кандидат по run_number, собирает его после
обязательных gates и отправляет immutable archive с manifest и digest. Receiver
сохраняет порядок запросов, блокирует apply через flock и атомарно меняет current.
Поздний старый кандидат/rerun не заменяет новый. Красный новый кандидат сохраняет
работающий релиз, но не выбирает прежнюю feature-ветку автоматически.

## Откат

Receiver сохраняет previous до переключения. При провале startup/health/SPA
восстанавливает previous и перезапускает только itmap@main. Первая неудачная
установка останавливается. failed_rolled_back остаётся ошибкой; rollback_failed
требует администратора. Не удалять релизы или журнал sequence ради повторения.

Ручное обновление также требует единой блокировки переключения/проверки/отката,
проверенного previous и immutable root-owned релиза. Откат кода **не откатывает БД**;
не восстанавливать старый dump автоматически. Backup/restore принимает владелец.

## Перенос после спринта

Подготовить основной сервер и независимую MariaDB; согласовать backup/restore,
финальную остановку записи, целостность и план возврата. Проверить app/HTTPS,
затем переключить main target. Остановить временную main-службу после проверки
перехода и запретить дальнейшую main-доставку на временный сервер. Только после
этого перепрофилировать его под точный ref1.2. Старые базы/backup автоматически
не удалять. Рабочий GPT Sites/D1 не переключать без отдельного cutover.
