# Руководство администратора

## Парсинг вакансий агентств

В «Настройки → Парсинг вакансий → Источники и правила» добавлен переключатель «Парсить вакансии агентств». По умолчанию он выключен, включая существующие установки и старые бэкапы без этой настройки. Включение нужно сохранить. Пока он выключен, новые сборы и следующие этапы агентств не начинаются; ручная диагностика, классификация, загрузка текста, структурирование и импорт тоже соблюдают выключение. Полученные ранее карточки/личные данные остаются доступны.

После включения агентства используют те же выбранные источники, фильтр избранного, период и бюджеты. HH собирается Apify, собственные сайты и другие поддерживаемые списки — Firecrawl. Агентства с незаполненными или неподдерживаемыми ссылками пропускаются. Отдельных расписаний или моделей не создаётся. Переключатель «Проверять все компании и включённые агентства» при включённых агентствах распространяется и на них; при снятом флаге нужны избранные агентства текущего администратора.

Вакансии проходят те же JEV/полный текст/структурирование/конечные роли/автоматический импорт/личную релевантность. Они привязываются к карточке агентства и получают тип «агентство». Реальный скрытый работодатель автоматически не создаётся из предположений модели. Совпадение числового ID компании и агентства не смешивает их записи; точное совпадение URL с чужой публикацией не перепривязывает её.

Выключение сохраняет очередь и курсоры. Ожидающие задания агентств продолжаются после включения, в пределах прежних сроков/лимитов; запущенный запрос может завершиться у провайдера, но сервер проверяет переключатель перед сохранением результата. Ручная проверка доступна также из вкладки вакансий агентства; в общем списке организации различаются пометкой «Агентство».

Бэкап38 сохраняет связь agency_id и переключатель; полные14–37 поддерживаются с пустой связью агентства и безопасным выключенным значением по умолчанию. Обновление не включает реальные запросы агентств автоматически.


Если rabota сохранил часть вакансий, но не дал продолжения, scan остаётся неполным (listing_incomplete), без отметки полного успеха. Следующая свежая проверка назначается через выбранный интервал; неполный результат не отключает источник навсегда и не вызывает немедленный повтор.

Для списков rabota.ru Firecrawl получает onlyMainContent=false: очистка основного контента может вырезать шапки самих карточек. Другие источники и detail сохраняют default=true. Это внутренний boolean транспорта/policy, без произвольных provider опций в HTTP. Card pairing ограничен настоящим закрывающим тегом root карточки, footer title не используется.

Rabota: заголовок карточки может находиться вне пустой мобильной ссылки. Адаптер связывает heading и vacancy URL только внутри одного блока vacancy-preview-card; карточка с несколькими разными ID не получает догаданный заголовок. Чужие hosts и обычные проверки пары остаются обязательными.

После исправления адаптера владелец может точечно поставить rabota.ru одной компании в штатную очередь через диагностический target queue. Источник должен быть настроен и выбран; пауза, избранное и текущая revision соблюдаются. Это не сброс всей очереди и не ручной импорт.


rabota.ru поддерживается Firecrawl наравне с остальными обычными источниками. Он используется только у компаний с заполненной ссылкой и при выборе rabota.ru в парсере. Страница компании автоматически переводится на вкладку вакансий. Если сайт объявляет больше вакансий, чем удалось получить, и не даёт доступного продолжения, сбор остаётся частичным; это не означает проверку всех вакансий работодателя.

Актуально на 21.10.2026, редакция документации 205. Бэкап v37; рейтинг компаний v5. Это инструкция по эксплуатации, без необходимости программировать.

## Извлечение списка ЮMoney

ЮMoney поддерживается отдельным адаптером. При стандартных настройках новый обход читает публичный каталог Tilda обычными HTTP GET: главную страницу, явную ссылку полного списка `/vacancies`, затем порции каталога. Адрес и параметры берутся из публичной конфигурации страницы; произвольные адреса и исполнение JavaScript не используются. Продолжение сохраняется между порциями. На21.10 публичный каталог подтвердил9вакансий:6+3. Это наблюдение конкретного ответа, не постоянное ожидаемое количество.

Запросы этого списка не расходуют кредиты Firecrawl; в результате показываются прямые HTTP-запросы и объявленное каталогом количество. Настройки включения источника, избранного и расписания общие с конвейером. Старый начатый Firecrawl-обход завершается своим прежним транспортом; вручную заданные класс/префикс сохраняют HTML-путь. Публичный каталог не заменяет загрузку полных описаний и последующие этапы JEV/структурирования/импорта.

Полнота подтверждается только непрерывным обходом всех порций, согласованным общим количеством и корректными парами названия/ссылки. Повторная порция, изменение количества, блокировка или неизвестная конфигурация оставляют результат неполным. Найденные корректные пары сохраняются, но дата полного успеха не обновляется. Повтор сохранения уже полностью сохранённого результата не сдвигает дату успеха.

## Ограничения источников вакансий

Подтверждённые корпоративные страницы Bip.ru `/company` и Rubytech `/career/` не обходятся как собственные списки: они направляют на HH. Ссылка в каталоге и история сохраняются, отдельный источник HH доступен. Исправленная ссылка на собственный список не попадает под это исключение.

Если Getmatch возвращает «Не смогли загрузить данные», результат получает причину `listing_unavailable`, без отметки пустого списка или полного успеха. Следующая свежая проверка назначается через выбранный интервал источника. Немедленный платный повтор не выполняется; ошибка остаётся в истории. Это состояние отличается от ошибки правила извлечения.

## Справочник ролей вакансий

Стандартные сочетания ролей, ошибочно созданные старой инициализацией в «Сохранённых ролях», переносятся на отдельные конечные роли исходных категорий при запуске новой серверной версии. Переносятся также метки происхождения от парсера; другие назначения и данные вакансии сохраняются. Пустая служебная категория удаляется. Несколько названий через точку с запятой или запятую больше не создают одну новую роль; инициализация заполняет только отсутствующие назначения. Неизвестные или настроенные вручную роли автоматически не удаляются. Старые бэкапы без дерева разбирают стандартные сочетания тем же способом.

В «Настройки → Роли» доступно дерево ролей. Нажатие на название категории со стрелкой раскрывает или сворачивает её потомков; это действие доступно с клавиатуры. Можно добавить корень или дочерний узел, переименовать, переместить, изменить порядок и удалить роль. Родитель выбирается по полному пути; сама роль, её потомки и используемые конечные роли исключены из вариантов. При перемещении ID и назначения вакансий сохраняются. Во время сохранения действия заблокированы; ошибка отображается рядом с деревом и позволяет повторить попытку. В вакансиях выбираются только узлы без детей. Сервер блокирует дубликаты названий, циклические перемещения и удаление роли, если она используется вакансией или содержит дочерние узлы. Добавление ребёнка превращает прежний конечный узел в категорию, поэтому заранее перенесите его назначения на отдельную конечную роль.

Начальные ветви: `IT Manager` с ролями «Менеджер проектов», «Менеджер продуктов», «Руководитель разработки»; `Журналист` с ролями «Редактор» и «Дата-журналист». Сохранённые прежние значения не удаляются. JEV рассчитывает релевантность и отдельно классифицирует заголовки по корневым направлениям. Дочерние роли на этом этапе автоматически не назначаются.

## Полномочия и общие данные

Администратор Eugene управляет общими вакансиями, каналами, контактами и переносом данных. Nastya и Demo работают со своими откликами, задачами и признаками избранного/скрытия. Административная роль не переключает личный контекст на другого пользователя.

В «Настройках» вкладка «Общие» содержит прежние операции, вкладка «Резюме» — личный текст кандидата до 20 000 символов, вкладка «Документация» — эти руководства, вкладка «Промты» — общие системные Markdown-тексты: «Сопроводительное письмо» до 15 000 символов, «Релевантность» до 5 000. Вкладка и API доступны только администратору; кандидаты не могут задавать промты. Документы доступны только для чтения; кнопка «Скачать .md» сохраняет исходный Markdown выбранного раздела.

## Добавление и обновление организаций

1. Скачайте полный Excel-шаблон компаний и агентств. Прочитайте лист «Инструкция» и [форматы переноса](TRANSFER_FORMATS.md).
2. Сохраните свежий бэкап перед массовым изменением.
3. Выберите режим добавления новых организаций либо обновления существующих. Не меняйте постоянные ID; номер места в рейтинге не является ID.
4. Загрузите файл, изучите итог: сколько добавлено, обновлено, пропущено и какие строки ошибочны. Импорт таблиц допускает частичное принятие строк.
5. Исправьте отклонённые строки и повторите импорт в подходящем режиме. Обновите страницу, чтобы увидеть результат.

Для офисов важна точная связь по названию компании; для отзывов — постоянный ID. До трёх контактов ответственных за найм на организацию. Не переносите DreamJob из источников отзывов в одноимённое поле источников вакансий: это разные данные.

## Рейтинги

Компания получает до 100 баллов: роли — 5, отсрочка/аккредитация — 15, отзывы — 20, WLB — 20, зарплаты — 20, оборот — 10, ИИ — 10. Отдельных баллов за московский офис и прозрачность нет.

Балл ИИ: 0, 5 или 10; отсутствие оценки отличается от нуля. Для 5/10 необходимы факты и источники: внедрение, направление, продукт, вакансии или оборудование. Доступ к ChatGPT сам по себе не даёт баллы. При обновлении пустые поля ИИ сохраняют прежнюю оценку; для снятия баллов укажите 0.

У агентств отдельная логика оценок. После изменения исходных оценок используйте «Пересчитать рейтинг»; импорт сам по себе не заменяет эту операцию для агентств.

## Вакансии, каналы, контакты

Общие вакансии может создавать, менять и удалять администратор. Количество вакансий на организацию не ограничено. Excel поддерживает добавление и обновление по ссылке. Ссылка уникальна; нельзя назначить существующую ссылку другой организации.

В карточке компании или агентства, на вкладке вакансий, кнопка «+ Добавить вакансию» открывает форму справа. «Редактировать» доступно у каждой вакансии и в панели полного текста. Владелец задан карточкой и при редактировании сохраняется.

Обязательны название, уникальная HTTP(S)-ссылка, роль, уровень и полный текст Markdown (до 100 000 символов). Можно заполнить зарплату от/до в рублях за месяц (целые неотрицательные числа; одна граница допустима), даты публикации и загрузки, личную релевантность 0–100, тему и Markdown-текст сопроводительного письма (512/2000 символов). Для агентства можно указать реального работодателя. Есть предпросмотр Markdown и подтверждение закрытия при несохранённых изменениях. Ошибка сохраняет введённые значения в форме.

В блоке Telegram можно выбрать существующий канал и заполнить ссылку на сообщение и контакт. Выбор уже привязанного канала обновляет его источник; выбор другого добавляет новый. Пустой выбор сохраняет имеющиеся источники. Удаление источников этой формой не выполняется. ID, архивность и служебные даты не вводятся вручную; личные избранное/скрытие остаются в панели просмотра. Сохранение вакансии не меняет существующие отклики, задачи и личные признаки других пользователей.

В «Список → Каналы» администратор нажимает «Добавить» и вводит название и ссылку
на Telegram-канал. Форма сохраняет черновик при ошибке и предупреждает при уходе
без сохранения. В каждой строке есть кнопка удаления с подтверждением;
при отказе сервера строка сохраняется с объяснением причины. Эти кнопки недоступны
соискателю; POST/DELETE дополнительно защищены проверкой роли на сервере.
В «Настройках» блока управления каналами больше нет.

Каналы содержат название, ссылку/username, комментарий и дату успешной проверки. Контакты ответственных за найм — общие; контакты рекрутера в отклике — часть личной записи соискателя.

## Резервная копия и восстановление

Бэкап начиная с v18 включает резюме всех пользователей (user_profiles). При восстановлении v14–17 резюме назначения сохраняются с предупреждением, поскольку в старых копиях этого раздела нет. Начиная с v18 раздел обязателен. Системные промты входят в v20; более старые копии при восстановлении сохраняют нынешние системные промты с предупреждением. Личные письма входят начиная с v21; v14–20 сохраняют существующие письма назначения с предупреждением.

1. Скачайте JSON-бэкап и храните его в защищённом месте: он содержит личные данные и зашифрованные подключения календарей.
2. Для восстановления выберите файл до 25 МиБ. Предварительная проверка покажет количество таблиц, строк и предупреждения.
3. Прочитайте предупреждения и подтвердите замену данных. Это затрагивает данные всех пользователей, а не только открытый аккаунт.
4. При успешном восстановлении обновите приложение. Проверьте компании, вакансии, отклики, задачи, резюме/письма, промты/модели и графики диагностики.
5. Для возобновления парсинга проверьте подключения, включите планировщик и нужные сервисы. Apify и платное разрешение восстановление выключает; облачный триггер нужно привязать заново. Временная очередь и блокировки в JSON не переносятся.

Полные v14–39 поддерживаются с ограничениями старых версий. v1–13 требуют отдельного преобразования; изменять номер версии вручную нельзя. Ошибка «неизвестная таблица» или «неизвестный столбец» требует проверки разработчиком, а не удаления разделов из файла.

Актуальный v39 сохраняет 52 прикладные таблицы, включая дневную историю ошибок и происхождение вакансий для фильтра воронки по парсеру. В v14–38 этих двух разделов нет: появится предупреждение, отсутствующая история на новом сервере не будет выдумана.

Бэкап не содержит исходный код, пароли, облачные расписания и настройки среды. Для переноса на другой сервер нужны исходники, SQL-миграции, настройки и прежний SESSION_SECRET для расшифровки подключений календаря и API-ключей либо их повторное подключение. Отдельный бэкап кода из Git не содержит живую базу; отдельно сохраняйте JSON-бэкап данных.

## Если операция завершилась ошибкой

При проблеме входа проверьте выбранный аккаунт; настройка паролей выполняется через секреты среды, не через эту вкладку. При отказе API в доступе не используйте чужую сессию. Для ошибки импорта сохраните файл и отчёт со строками; для бэкапа — исходный файл и текст ошибки. Не повторяйте восстановление вслепую. Передайте разработчику действие, время, сообщение и версию формата, исключив пароли и токены.

## Нейросети → OpenRouter

Доступно только администратору в отдельной вкладке настроек. Введите API-ключ OpenRouter и нажмите «Сохранить ключ». Сервер зашифрует ключ и попробует обновить модели. После сохранения поле очищается; видны только последние четыре символа. «Проверить подключение» проверяет действительность ключа через внешний OpenRouter /api/v1/key без генерации текста. «Тестовый AI-запрос» отправляет короткую служебную фразу через общий маршрутизатор; резюме и вакансии в этом тесте не передаются.

Таблица содержит только бесплатные текстовые модели с контекстом от 262144 токенов и поддержкой рассуждений. Рейтинг: Intelligence, затем Agentic, Coding, контекст. Отсутствующие оценки показаны как «нет данных»; такие модели находятся после моделей с Intelligence. Основная модель — первая в рейтинге. Последняя фактически использованная — модель из последнего успешного ответа: она может отличаться из-за последовательного переключения №1 → №2 → №3. Следующая модель вызывается только после неудачи предыдущей. Результат тестового запроса показывает модели в порядке попыток. Следующий тест снова начинается с первой в рейтинге. Для сопроводительных писем активной становится модель, успешно ответившая на последний тест: генерация начинает с неё, а при ошибке или непригодном формате переходит к следующей по рейтингу. Эта модель отдельно указана в настройках.

Список обновляется после сохранения ключа, вручную и при обращении после шести часов. При сбое остаётся прошлый список с предупреждением. Если подходящих моделей нет, AI-запросы недоступны. ## ChatGPT через OpenAI API

Для каждого общего промта отдельно задаются OpenRouter или ChatGPT (OpenAI API),
модель и уровень рассуждений. OpenRouter использует последнюю успешную тестовую
модель и следующую по рейтингу при ошибке. OpenAI вызывает выбранную модель.
Настройки модели и текст промта сохраняются отдельно, только администратором.
API-ключ вводится только администратором во вкладке «Нейросети» → «ChatGPT».
Он хранится AES-GCM ciphertext с отдельным доменом openai:v1; после сохранения
интерфейс получает только маску последних 4 символов. Плагин для своего ключа не нужен.
API оплачивается отдельно от подписки ChatGPT; плагин не меняет способ оплаты.
GPT-6.1 Luna по умолчанию только если доступна в API аккаунта; иначе показывается
фактическая модель из рекомендуемых. Неизвестные capabilities используют default
модели, без неподтверждённых reasoning-параметров. Смена выбора не заменяет письма,
которые уже сохранены. Пустая персональная релевантность импортированной вакансии автоматически рассчитывается JEV для владельца планировщика по его сохранённому резюме. Нужны заполненные резюме/промт и выбранная JEV; пропуски ставятся в очередь порциями. Сохранённые оценки не меняются автоматически. Ручной пересчёт одной вакансии по клику использует выбранную в настройках модель.

## Модель OpenRouter для релевантности

Для промта «Релевантность» при провайдере OpenRouter выберите «Лучшая бесплатная» или «JEV» и нажмите «Сохранить модель». Выбор общий для пользователей, сохраняется отдельно от текста промта и модели OpenAI. По умолчанию остаётся бесплатный режим. JEV использует платную `typesafe/jev-1.13`, сохранённый ключ и баланс OpenRouter, без перехода на бесплатные модели. При сохранении модель проверяется в отдельной части каталога OpenRouter для модальности `decisions`; обычный текстовый каталог JEV не содержит. Для сопроводительного письма этот выбор не отображается: JEV возвращает оценки, а не текст. Сохранение выбора не запускает пересчёт вакансий; для пересчёта отдельной вакансии пользователь нажимает её поле «Релевантность» в списке.

Под выбором модели показана примерная стоимость 1000 ответов в рублях. Расчёт использует фиксированный курс 1 $ = 85 ₽ и допущение: 15 000 русских символов ≈ 7 500 входных токенов, целое число от0 до100 ≈ один выходной токен. Для бесплатного режима выводится0 ₽. Для JEV тариф входа, выхода и возможная фиксированная цена запроса загружаются из текущего каталога OpenRouter; для OpenAI используется проверенный тариф выбранной модели. Это ориентир: служебный формат и токены рассуждений могут увеличить фактическую сумму.

Пересчёт одной вакансии использует текущий общий промт «Релевантность», выбранную модель и резюме пользователя. JEV получает объект state с resumeMd, vacancyTitle, vacancyMd и необязательным salary (from/to, RUB/month; одна граница может быть null). Расчётная вилка работодателя не передаётся. Общий промт описывает профессиональное соответствие, зарплата нейтральна для оценки. Редакция21.10 уточняет основную функцию, критические компетенции, разницу между управлением и hands-on/ML, продуктовым и административным опытом, сопоставимость масштаба. SQL0080 обновляет только наблюдённую relevance revision2 с точным прежним текстом и датой; конкурентная правка сохраняется. Сохранение промта не пересчитывает имеющиеся оценки. JEV через Decisions API возвращает score на десяти уровнях criteria, от0 до9; дробное значение допустимо. Сервер переводит его в целое0–100 по round(score×100/9), интерфейс добавляет знак%. Промт не требует от JEV генерации JSON, процентов или объяснения; формат задаёт адаптер. Для текстовых моделей адаптер отдельно требует JSON с relevance от0 до100. Администратор задаёт промт/модель, каждый пользователь пересчитывает собственную оценку. Пустые входные данные и ошибки модели сохраняют предыдущую оценку.

## Классификация вакансий

В «Настройки → Промты» корневые роли получают собственный Markdown-промт классификации по заголовку, максимум 10000 Unicode-символов. Поля загружаются из дерева; дочерним ролям промты не назначаются. Сохранение проверяет версию и защищает от потери изменений в другой вкладке. Восстановление стандартного текста заполняет редактор, затем нажмите «Сохранить». IT Manager и Журналист получают начальные тексты по постоянному ключу, новая категория получает пустой промт. Точный прежний стандарт IT Manager обновляется общими критериями русских продуктовых ролей и Product Owner, без отраслевых ограничений; собственные правки не перезаписываются. Переименование не меняет привязку по ID. Перемещённый в дочерние узел временно не участвует, его настройки сохраняются. Перед удалением настроенной роли выключите парсинг и очистите промт. Доступ только администратору.

Список rabota.ru загружается постранично до окончания подтверждённой пагинации. Между серверными порциями сохраняются номер следующей страницы и уже полученные пары; за одну порцию сохраняются до10 пар. Прежние ограничения трёх страниц и200 вакансий не ограничивают суммарный список rabota. Повтор страницы, разрыв диапазона и недоступное продолжение не считаются полным успехом. Бюджеты Free/Hobby и область избранных продолжают действовать. Вакансия с заголовком без текста обязанностей не отправляется на платное определение роли; отсутствие текста показывается ошибкой загрузки.

В «Настройки → Парсинг вакансий» переключатели есть только у корней, потомки показаны для информации. Отключение сохраняет промт и вакансии. Новая категория выключена, пустой промт пропускается. Переключатель сохраняется сразу, конфликт версии требует обновления.

Проверка доступна в «Парсинг вакансий»: введите заголовок до 500 символов и нажмите «Проверить». Один запрос JEV даёт независимые match/reject по активным направлениям. В таблице показаны использованные версии, модель, общее время и время запроса. Стоимость показывается только из usage.cost провайдера по курсу85₽/$1; без суммы отображается отсутствие данных. Ошибка отдельного направления не равна отказу. При технической ошибке без совпадений повторите проверку. Тест не создаёт вакансий, не назначает роли и не запускает Firecrawl.

Промежуточное хранилище первичных публикаций доступно через административный API /api/vacancy-candidates. Полноценная вкладка парсера не добавлена. Такие записи не показываются среди основных вакансий и не учитываются в их лимитах/статистике. Повторное обнаружение обновляет lastSeenAt и метаданные; заголовок сохраняется без перевода/исправления. История решений и исходные отвергнутые публикации сохраняются. Включение/отключение направлений и редактура промта меняют вычисляемое состояние без массовой записи в базу.

Для сквозной проверки сохраните публикацию POST /api/vacancy-candidates, затем POST /api/vacancy-candidates/:id/classify с {}. GET /:id покажет сохранённые решения и историю. Повторный вызов без force переиспользует актуальные результаты; {force:true} явно запускает новый запрос. Нет классификатора: no_active_roles. accepted означает хотя бы один текущий match; rejected только полный успешный отказ; classification_error требует повторить отсутствующие решения. Роль с историей классификации удалить нельзя, её можно выключить или переместить. Полный JSON-бэкап30 переносит промежуточное хранилище и историю; старый14–28 восстанавливает этот раздел пустым с предупреждением. Тестовые записи в рабочую базу разработчиком не добавлялись.

## Классификация первичных вакансий (15.10.2026)

После «Сохранить найденные» новые/устаревшие первичные вакансии автоматически ставятся в JEV; проверка источника без сохранения не вызывает JEV. В «Настройки → Парсинг вакансий → Диагностика → Пакетная классификация» есть живые счётчики и запуск до50ожидающих: всё, компания, её источник или ID одной первичной записи. ID можно увидеть в результатах пакета/API. Связанные с main импортированные записи не входят в очередь.

Сначала включите корневые направления и сохраните непустые промты/ключ OpenRouter. Без активных направлений публикации не отклоняются. JEV оплачивается через OpenRouter и работает независимо от Firecrawl Free/Hobby или исчерпания его бюджета. Обычный запуск переиспользует актуальные решения. Принудительный пересчёт требует отдельного подтверждения новых платных обращений и также ограничен50записями.

После202пакет лишь поставлен в очередь; завершение, pause/error, число готовых/оставшихся, время и доступная стоимость показываются по данным сервера. Неизвестная стоимость выделена отдельно и не включается в подтверждённую сумму. Начатая фоновая обработка продолжается после закрытия вкладки в ограниченном серверном окне; при паузе нажмите «Продолжить пакет». Остаток сохраняется в D1, успешные направления повторно не оплачиваются. После неопределённой сетевой ошибки новые проверки могут ждать освобождения слотов до5минут. Restore отменяет старые пакеты; необходимые решения выбираются заново из восстановленных данных. Основные вакансии, полные тексты и дочерние роли этот этап не создаёт.

## Полные тексты подходящих вакансий

Откройте «Настройки → Парсер → Обработка полных текстов». После актуального положительного JEV система ставит первичную вакансию в обработку: сохраняет исходный Markdown, затем структурированные поля. Для уже принятых записей нажмите «Обработать ожидающие подходящие вакансии», пакет — до20. Статистика раздельно показывает загрузку, LLM, ошибки и готовность к импорту.

Промт «Структурирование вакансии» и модель находятся в «Настройки → Промты». Лимит10000 Unicode-символов в редакторе/API/БД, сохранение с CAS. Текущий стандарт использует OpenAI GPT-6 Luna; доступны существующие настройки провайдеров. Стандартный промт можно восстановить в редакторе и сохранить. Миграция0077 обновляет только точный прежний стандарт с prompt_revision0; пользовательские тексты/модели/редакции сохраняет.

Новая обработка обязана выбрать Middle, Senior, Lead или Head. Правила учитывают самостоятельность, сложность, управление одной командой или направлением; при неоднозначности выбирается менее высокий обоснованный уровень. Если признаков Senior/Lead/Head нет, Middle — базовая категория этой шкалы. Это оценка приложения, а не утверждение работодателя; текст вакансии ею не дополняется. JEV по-прежнему отвечает за первичную классификацию и конечные роли, дополнительного вызова для уровня нет. Неизвестный/null уровень не принимается как успешный schema2 ответ.

В description_md модель должна максимально дословно сохранить содержание и порядок исходного текста; пересказ, сокращение, перевод и стилистическая правка запрещены. Разрешена техническая Markdown-разметка и удаление посторонней навигации/cookie/технических дублей. Это правило промта, а не доказательство побуквенного совпадения каждого ответа модели. Исходный Markdown хранится отдельно без изменений.

Изменение промта/схемы отменяет переиспользование прежнего LLM-результата при следующей обработке. Обновление само не выполняет массовый пересчёт ранее импортированных карточек; дозаполнение Сбера остаётся отдельной P2 задачей с защитой ручных правок.

Введите ID первичной вакансии для просмотра источника, JEV, безопасного Markdown, JSON, модели/времени/стоимости и истории. Неизвестная стоимость обозначена явно. Полный исходный текст не сокращается; если он превышает120000 символов, LLM-этап остаётся ожидающим с причиной.

Обычный повтор использует сохранённые этапы без новых запросов. Обновление исходной страницы требует отдельного подтверждения расхода Firecrawl и учитывает прежний общий бюджет Free/Hobby. Изменённый текст получает новую версию; одинаковый не копируется. Если пакет приостановлен, исправьте указанную причину и продолжите его. Готовность — промежуточный признак: создание основной карточки и дочерние роли относятся к следующей задаче.

## Безопасный перенос в основные вакансии

«Настройки → Парсер → Импорт подготовленных вакансий»: выберите до20 записей или введите первичные ID. «Проверить импорт» не меняет основные карточки. Если роли ещё не выбраны, отдельная кнопка использует промт «Определение роли вакансии» и модель из общих настроек; повтор открытия preview не вызывает LLM. Пустой результат роли сохраняется: уточните дерево или промт, а не запускайте бесконечные повторы.

Для каждой записи показаны компания, конечные роли, источники и таблица «Сейчас/После». Совпадение заголовка требует решения: связать с указанной основной карточкой или разрешить отдельную новую. После выбора повторите проверку. «Импортировать» с подтверждением применяет безопасные изменения. Автоматический импорт без подтверждения выключен.

Пакет сохраняет progress и выполняет до3 записей в одном окне. «Продолжить подтверждённый пакет» обрабатывает следующие записи; при смене данных заново проверьте затронутые ID. Ошибки/отсутствующая компания не удаляют подготовленный текст. В истории видны создание/обновление/пропуск, версии и изменённые поля. Основная карточка показывает дополнительные источники.

Ручные поля/роли, письма, отклики, персональная релевантность, избранное/скрытие и архив не перезаписываются. У старых непустых полей неизвестное происхождение, поэтому они сохраняются. Основная числовая вилка поддерживает RUB/month; иная валюта/период остаётся в описании и метаданных источника. Неподдерживаемые дополнительные поля не теряются: исходные JSON и Markdown остаются в промежуточной базе.


## Собственный планировщик

«Настройки → Парсинг вакансий» содержит четыре локальные вкладки. «Обзор» показывает очередь, последний цикл, расходы JEV/LLM, область сбора и сводку проблем. Общие кнопки запуска/паузы остаются над вкладками. «Источники и правила» содержит единственный редактор избранного/всех организаций, агентский переключатель по умолчанию OFF, типы источников, период1/3/7дней и корневые направления. Неподдерживаемые Telegram/DreamJob/Эйч перечислены отдельно, без переключателей. Дочерние роли раскрываются по запросу; редактор промтов открывается из этого экрана.

«Сервисы и лимиты» объединяет бюджеты JEV/LLM, Firecrawl и Apify; кредиты не суммируются с долларами. Подключения/платные профили и технические параметры раскрываются отдельно. Фильтр избранного из Firecrawl удалён только из интерфейса: один общий параметр сохраняется прежним сервером. Включение Firecrawl, тайм-аут и настройки сбора относятся также к автоматическому пути. Бюджеты/область сохраняют черновики при переходах между локальными вкладками и исходную CAS revision; конкурентное изменение не должно незаметно перезаписаться.

«Диагностика» показывает три группы: P1 критичные для конвейера (красный), P2 сбои обработки/полнота и известные проверки (янтарный), P3 сверка/улучшения (синий). Цвет дублируется текстом. У каждой задачи есть статус observed/verification/planned, описание, следующий шаг, дата и переход к инструменту; у сигналов очереди раскрываются затронутые организации и вакансии. Проверки ЮMoney/HH и старых уровней Сбера не выдаются за подтверждённые текущие сбои. Реестр известных проверок поддерживается в server/services/parser-issues.js; интерфейс не запускает их автоматически. Исторические failed показаны отдельно; текущая проекция учитывает область, отключённые агентства/источники и последующее восстановление. При превышении выборки120 заданий показано ограничение. Счётчики обзора не являются оценкой полноты всей базы.

В диагностике есть очередь с поиском по названию компании/агентства и фильтрами состояния/этапа, журнал, переключатель ручных инструментов (источник, тест заголовка, пакетная классификация, полный текст/уровень, импорт/дубли) и техническая проверка расписания. Инструменты загружаются при первом открытии и сохраняют состояние при локальном переключении. Открытие вкладки не вызывает платные запросы. Числовые приоритеты исполнения очереди0–100 не связаны с P1/P2/P3 списка проблем.

По умолчанию диспетчер приостановлен, бюджеты0, источники выключены. Новые организации/ссылки учитываются следующим тиком, выбирать компании по одной не требуется. При пустом выборе автоматическая обработка источников и их вакансий не запускается. Сохранение области не включает сервисы и не снимает паузу. «Запустить сейчас» выполняет до50 заданий/110с тем же серверным диспетчером. Пауза запрещает начало следующих заданий; отправленный запрос может завершиться.

Успешный HTTP-ответ rabota.ru с одним дефектом «нет текста обязанностей» повторно загружается один раз через минуту. Если повтор снова неполный, этап остаётся ошибкой; закрытые страницы, капча и прочие невалидные ответы не получают такой повтор. Старые ошибки этой точной формы восстанавливаются один раз через новую версию этапа без стирания истории.

Подходящая подготовленная вакансия автоматически импортируется без модерации через прежний безопасный механизм. Ручной блок импорта по-прежнему требует подтверждения. В автоматическом режиме совпадение только заголовка не блокирует импорт: при отсутствии подтверждённой связи создаётся отдельная карточка, решение сохраняется в истории. Точные связи по URL/ID и приоритет HH сохраняются; конфликт устойчивых ключей и некорректные роли остаются диагностическими исключениями. Очередь поддерживает серверные фильтры/пагинацию; повтор или отмена доступны для незапущенных/ошибочных заданий.

Бюджеты относятся только к автоматическому конвейеру, периоды по Москве. До платного запроса резервируется верхняя оценка по тарифу; неизвестные тариф/остаток блокируют запрос, неопределённое списание сохраняется в резерве. Генеративный OpenRouter остаётся бесплатным с max_price0; Firecrawl использует общую политику Free/Hobby. Подписку, допкредиты и повышение тарифа планировщик не включает. Расходы на письма сюда не входят.

Для облачного запуска Sites необходима проверенная привязка администратора. Через «Войти через ChatGPT» войдите в тот же сайт, сохранив администраторский сеанс Eugene, и нажмите «Привязать мою учётную запись ChatGPT». Подключите инструменты сайта через Plugins → Personal → Created by you. Подключённые расписания должны только вызывать scheduler_tick. В текущей установке используются два почасовых слота :00 и :30; редизайн не меняет их. До фактического вызова интерфейс честно показывает неподтверждённое подключение; локальная диагностика не выдаётся за запуск Automation.

Ручная проверка источника находится во вкладке «Диагностика» и не является обязательным шагом настройки автоматизации. Ранее настроенные адаптеры сохраняются. Единая область избранного/всех организаций редактируется только во вкладке «Источники и правила»; серверная совместимость старых форм сохранена, записи защищены редакциями.


Автоматический режим — основной путь: выберите источники/область, настройте Firecrawl, роли/модели и бюджеты, включите диспетчер. Облачный сигнал сам сохраняет найденные записи, классифицирует, загружает текст, структурирует, определяет конечные роли и безопасно импортирует. Подтверждать каждый этап не требуется. «Запустить сейчас» ускоряет один цикл, но не является обязательным продолжением каждого этапа. По достижении110с/50заданий остаток выполняется следующим сигналом; ожидание бюджета/лимитов и временные ошибки откладываются автоматически. Возможные дубли/невалидные данные требуют отдельного решения и не объединяются принудительно.

Во вкладке «Диагностика» ручные инструменты выбираются через «Что проверить». Кнопки классификации/текста/импорта относятся только к ручным пакетам и проверкам; они не блокируют работу собственного планировщика. Перед готовой очередью выполняются только короткие ограниченные сверки отсутствующей релевантности и известных остановок импорта из-за изменившихся зависимостей. После смены модели/промта устаревший импорт ставит актуальный этап; прежняя ошибка сохраняется в истории. Полный обход каталога не выполняется перед готовой очередью. Неоднозначные дубли и реальные ошибки модели не сбрасываются автоматически.

### Тайм-аут автоматической обработки

Если модель не успела ответить, очередь сохраняет причину `timeout` и повторяет этап автоматически после паузы6мин в пределах4 попыток. Уже загруженный Markdown и завершённые этапы используются повторно. Неполученный ответ не записывается как успешный или бесплатный: неизвестная стоимость учитывается прежним безопасным механизмом. Структурирование Luna и текстовое определение ролей начинаются при окне не менее90с; JEV определение ролей требует45с. При недостатке времени этап ждёт следующего тика без расхода попытки. Выбор модели повторно проверяется перед попыткой;15с остаются для сохранения результата. Старый код23.0 означал системное прерывание по времени, а не ответ модели; обновление0063 возвращает такие ошибочно завершённые задания текущей базы в очередь.

### Ускоренная почасовая серия

Единственная облачная автоматизация сначала подготавливает новую серию без обработки, затем запускает до5 последовательных серверных тиков за одно срабатывание. Срабатывание до границы часа больше не получает результат прежней серии. Сервер выдаёт продолжение, пока есть готовая работа, и ограничивает серию; автоматизация не планирует и не обрабатывает вакансии сама. Пауза/бюджеты/избранные/источники прежние. Один тик использует оставшееся время для коротких заданий и до двух независимых LLM-запросов.

Кнопка «Запустить сейчас» показывает промежуточный результат без минутного ожидания единого JSON. При закрытии соединения прерывается текущий запрос, завершённые этапы сохранены; очередь продолжит автоматизация.

Неподтверждённые необязательные salary_period/currency/tax, формат работы и дата публикации очищаются до null с записью исправлений в диагностике. Полный текст остаётся сохранённым. Неподтверждённые суммы зарплаты, некорректный JSON и обязательный текст по-прежнему блокируются. Обновление0064 повторяет только прежние ошибки проверки этих метаданных.

При автоматическом импорте неизвестный справочнику уровень вакансии остаётся в исходном тексте/метаданных; поле уровня основной карточки остаётся пустым. Это не мешает перенести остальную проверенную вакансию. Ручной выбор уровня использует прежний справочник.


## Устойчивость нейронных этапов парсера

Для структурирования выбран OpenAI/gpt-6-luna; для корневой классификации и назначения конечных ролей выбран JEV. Только если администратор явно выберет режим best_free OpenRouter, его подбор учитывает успешность и скорость моделей отдельно по типу этапа. После технического сбоя или некорректного ответа модель на15мин получает пониженный приоритет; следующая попытка выбирает другую допустимую бесплатную модель, если она доступна. После двух успешных замеров учитывается среднее время ответа. Если все варианты недавно ошибались, выбирается наиболее давно ошибавшийся; при единственной модели альтернативы нет. Платный fallback не включается, выбранный OpenAI не заменяется. Один автоматический запрос ограничен90с, повторов не больше прежнего max_attempts задания. Предыдущие failed не запускаются массово.

Облачный вызов передаёт SSE heartbeat и сохранённый прогресс, если вызывающая сторона поддерживает этот формат. При разрыве запрос к провайдеру отменяется, сохранённые этапы остаются; повтор просроченного идентификатора закрывает старую попытку и разрешает следующее серверное продолжение в пределах серии.


## Apify для HH

Если Actor списка завершился с ошибкой или тайм-аутом, сервер дочитывает его доступный dataset теми же порциями, сохраняет только пригодные записи и показывает частичный результат `apify_partial_run`. Успех полного сбора не выставляется, новый Actor для замены не запускается. Пустые или чужие записи не обходят проверку работодателя.
