# Базовый контракт HTTP перед переносом на Go

Источник: `server/routes/index.js`, `server/services/*route*.js`, `server/integrations/*.js`, `shared/contracts.ts`, `docs/API.md` (Sites v316, 23.10.2026).

`LEGACY_API_PATHS.json` создан командой `python3 scripts/extract-legacy-api.py` и перечисляет обнаруженные строковые пути со ссылками на места использования. **Это предварительный инвентарь, не исчерпывающая OpenAPI-спецификация**: часть путей построена динамически, вложенные маршруты обрабатываются отдельными модулями, а HTTP-методы зависят от веток выполнения.

## Неприкосновенные контракты при переносе

1. Прежние URL, HTTP-методы, статусы, имена полей и форматы ошибок сохраняются, если отдельно не согласовано изменение API.
2. `/auth`, `/logout`, `/api/session`, личные данные пользователя и права администратора требуют настоящей сессии. Ошибка аутентификации не должна превращаться в успех.
3. Данные каталога и списков вакансий загружаются компактными порциями; полные вакансии открываются отдельно.
4. Потоки генерации письма и жизненный цикл задач парсера имеют собственные контракты повторов, версий и идемпотентности.
5. `/api/internal/*`, `/mcp` и `/api/automation/*` не должны становиться общедоступными при переезде.
6. Экспорт/импорт и JSON-backup v39 необходимо сверять с настоящим приватным дампом **только в изолированной тестовой среде**.
7. Новые маршруты на Go вводятся постепенно: если портирование не закончено, отвечать `503`/`501`, а не синтетическими успешными данными.

## Группы API, которые требуют интеграционных тестов

| Группа | Главное, что сверить |
|---|---|
| Сессии и авторизация | cookies, роль, TTL, CSRF/origin, status codes |
| Компании/агентства/карта | projection, фильтры, кеш, pagination |
| Вакансии/роли | полные карточки, CRUD, idempotency, ссылки |
| Отклики/задачи | owner scope, CAS, дедупликация, календарь |
| Настройки ИИ/резюме | роль администратора, лимиты, revision |
| Письма/релевантность | SSE/потоки, retry, единственность генерации |
| Парсеры/планировщик | locks, очередь, источники, сохранение состояния |
| Экспорт/восстановление | форматы, версии, связность, безопасность |

## Что ещё предстоит в рамках 1.1.02

Для приёмки **полного** API-контракта нужно автоматически запросить работающий оригинал в отдельной локальной среде с синтетическими данными, сохранить эталонные запросы/ответы, затем прогнать их на Go. Исходная историческая сборка без SQL-миграций и реальной D1 не может заменить этот шаг. Изолированная база и секреты production для контрактных тестов не требуются.
