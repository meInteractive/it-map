# Сверка схемы перед переходом

`itmap-schema-audit` сравнивает метаданные активной MariaDB с полной доверенной
базовой схемой проекта. Сборка требует `go build -tags mariadb ./cmd/itmap-schema-audit`.
Для явного запуска нужно установить `ITMAP_SCHEMA_AUDIT=1` и переменные
`DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`; БД допускается только
локальная. Секреты передаются через защищённое окружение, не через аргументы.

Команда открывает транзакцию только для чтения, выполняет SELECT версии и
information_schema, затем откатывает транзакцию. Она не читает бизнес-строки,
не создаёт и не изменяет объекты и выдаёт только фиксированные категории
`schema_audit_compatible`, `schema_audit_mismatch_or_incomplete` или
`schema_audit_unavailable`. Неизвестная таблица или отличающиеся метаданные
приводят к отказу; в такой ситуации нельзя автоматически запускать миграцию.
Инструмент сверяет именно базовую схему, а не экспериментальные расширения.
Для точной проверки нужна полная видимость метаданных, включая триггеры.
У ограниченной учётной записи приложения триггеры могут быть невидимы: тогда
отказ не доказывает дефект схемы. Сверку выполняет назначенный администратор;
не следует расширять права runtime-пользователя только ради аудита.

Сверку проводить без параллельного изменения схемы: information_schema не
предоставляет этой команде защиту от внешнего DDL. Успех не подтверждает
состояние строк, generation, ledger, полноту или восстановимость резервной
копии и не является разрешением на переключение worker.
